## §5. `ISeasonClock` / `ILeaderboardRepository` 추상화 시그니처

> 목적: Phase 4(Sp05) 로컬 구현 ↔ Phase 5(Sp06+) Firebase 구현 2~3h 스왑 비용 유지.

### §5.1 `ISeasonClock`

```csharp
namespace GodBlade.Runtime.Season {
  public interface ISeasonClock {
    string CurrentSeasonId { get; }             // "s1", "s2", ...
    System.DateTime GetSeasonStartUtc();
    System.DateTime GetSeasonEndUtc();
    bool IsSeasonEnded();                        // UtcNow >= GetSeasonEndUtc() or Remote Config signal
    event System.Action<string> OnSeasonRolledOver; // Phase 5 Remote Config 이벤트 훅
  }

  // Sprint 05 구현
  public sealed class ManualSeasonClock : ISeasonClock { /* SeasonConfigSO 참조 */ }

  // Phase 5 이월
  public sealed class RemoteConfigSeasonClock : ISeasonClock { /* Firebase.RemoteConfig */ }
}
```

- **결정론 주의**: `IsSeasonEnded()`는 `DateTime.UtcNow` 직접 비교 금지 → **`ITimeProvider` 주입**으로 테스트 가능화 (Sp03 `IdleTicker` 시계 가드 패턴 재활용).

### §5.2 `ILeaderboardRepository`

```csharp
namespace GodBlade.Runtime.Season {
  public interface ILeaderboardRepository {
    System.Threading.Tasks.Task<bool> SubmitAsync(SeasonLeaderboardEntry entry);
    System.Threading.Tasks.Task<System.Collections.Generic.IReadOnlyList<SeasonLeaderboardEntry>>
      GetTopAsync(string seasonId, int limit);
    System.Threading.Tasks.Task<SeasonLeaderboardEntry?> GetMyEntryAsync(string seasonId, string playerId);
  }

  // Sprint 05 MVP
  public sealed class LocalLeaderboardRepository : ILeaderboardRepository { /* JSON */ }
  public sealed class InMemoryLeaderboardRepository : ILeaderboardRepository { /* Edit-mode 테스트용 */ }

  // Sp06 Firestore
  public sealed class FirestoreLeaderboardRepository : ILeaderboardRepository { /* orderBy+limit */ }
}
```

- **Sp06 주간 이벤트 재활용**: 메모리 `project_sp06_plus_lever_decisions.md` Sp08 주간 이벤트에 `ILeaderboardRepository` 동일 인터페이스로 재투입 예정 → Sp05에서 **인터페이스 경계 안정화** 필수.

## §6. `MigrateSeasonalToPermanent(float retainRatio=0.5)` 5 사이드이펙트 배선 순서

> **순서 엄수 — 순서 뒤집히면 PP 영구 유실 가능** (Sp02 W2 §4.2 I5 불변식).

| 순 | 동작 | 근거 | 순서 위반 시 결과 |
|----|------|------|--------------------|
| **1** | `seasonEnding=true` 플래그 선행 저장 | Sp05 설계 §3.2 + CP-M25 | 이중 발화 → 2차 호출에서 Seasonal 0에 50% 적용 → Permanent 증가 0 but 백업 덮어씀 |
| **2** | `IdleTicker.Instance?.FlushCatchUp(forceImmediate: true)` | Sp05 §3.2 신규 부수 효과 4 + CP-M26 | 방치 누적 PP가 `Seasonal` 채널에 미반영 → 마이그 후 Permanent 직행 (비율 미적용, 유저 이익·시스템 손해) |
| **3** | `prestige.v1.json.bak` 백업 생성 + `prestige_season<N>_pre_migrate.json` | Sp05 §2.5 복구 3단계 | 중간 크래시 시 복구 불가 |
| **4** | `PlayerPrestigeState.MigrateSeasonalToPermanent(retainRatio)` 호출 | Sp02 W2 §4.3 의사코드 | — |
| **5** | `OnSeasonEndMigrationCompleted` 이벤트 발화 + `SeasonEndModal` UI 트리거 + `maxFloor` 스냅샷 저장 + `MilestoneGranter.ResetForNewSeason()` | Sp05 §3.2 + Q3 C안 (스냅샷 보존) | UI 없이 PP 반토막 → 유저 혼란 |

- **추가 경고**: 2↔3 순서 바꾸면 백업 파일이 "방치 미반영 상태"로 저장 → 복구 시 최근 방치 PP 유실. **반드시 FlushCatchUp 먼저, 백업 다음**.
