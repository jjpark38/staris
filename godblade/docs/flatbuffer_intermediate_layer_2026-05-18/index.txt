## 3. FlatBuffer 선택 이유 3건

| 후보 | 빌드 검증 | Unity 호환 | Web 호환 | 스키마 진화 | 평가 |
|------|----------|----------|----------|------------|------|
| Cap'n Proto | A (capnp 컴파일) | B (Unity binding 미성숙) | A (capnp-ts) | A | 비추 (Unity 약점) |
| Protobuf | A (protoc) | A (protobuf-net) | A (protobuf.js) | A | 보류 (런타임 reflection 약점) |
| **FlatBuffer** ★ | **A (flatc)** | **A (Google C# binding 검증)** | **A (flatbuffers JS)** | **A (forward/backward)** | **채택** |
| JSON 직접 | C (스키마 검증 0) | A | A | C | 비추 (검증 없음) |
| MessagePack | B (스키마 옵션) | B | A | B | 비추 (Unity 약점) |

**FlatBuffer 채택 3 사유**:
1. **빌드 타임 검증** — `flatc` 컴파일러가 `.fbs` 스키마 위반 즉시 빌드 실패 → 한가영 0 편차 원칙 sync
2. **Unity·Web 동시 호환** — Google C# binding (`FlatBuffers.dll`) + flatbuffers JS 양 클라 1급 지원
3. **zero-copy parsing** — Unity 런타임 메모리 부담 0 (정현우 라이브 안정성 원칙) / Phaser 임베드 시 초기 parse 비용 0

차도윤 발화 가정 인용: "도윤입니다. flatbuffers JS 패키지 검증했고 모노레포 `packages/shared` 에 `.fbs` 단일 source 박을 수 있습니다. Phaser asset preload 시 binary 1회 fetch + zero-copy 로 60fps 영향 0. 임재훈 부하 테스트 통과 가정."

## 4. 빌드 파이프라인 3 layer

```
[Layer 1] Datasheets/*.tsv (윤서아 시트 single source)
              |
              | TsvReader (정현우 + 김민준 공동 소유, Sp02 이월)
              v
[Layer 2] packages/shared/schema.fbs (FlatBuffer 스키마)
              |
              | flatc 컴파일러
              | (CI/CD GitHub Actions 자동)
              v
[Layer 3a] Unity SO export (정현우)         [Layer 3b] Phaser JSON export (차도윤)
              |                                       |
              v                                       v
   Unity6/Assets/.../GeneratedSO/.asset       webgame/public/data/*.bin
              |                                       |
              v                                       v
   AddressablesGroup (라이브 핫픽스)         Phaser asset preload (Vite manifest)
```

**한가영 검증 라인** (Layer 2 → Layer 3 사이):
- `tools/balance/regression_200F.ts` — 한가영이 Layer 3a (Unity) ↔ Layer 3b (Phaser) 양측 binary 로드 후 200F 4.255 baseline 0.12% 편차 보존 검증
- 편차 0.5% 초과 시 빌드 실패 + Slack 알림 (한가영 페르소나 "0 편차 원칙")

## 6. 외주 ~40h 발주 시점 vs Self-build 헷지

### 옵션 A — 외주 ~40h 발주 (직전 정현우 회신 = 2026-05-15)

| 항목 | 내역 |
|------|------|
| 작업 범위 | flatc 컴파일러 CI/CD 통합 + TsvReader → fbs 자동 변환 + Unity·Phaser dual export 보일러플레이트 |
| 외주 비용 | ~40h × 시간당 비용 = 별도 PD 결정 |
| 장점 | 정현우 본업 (Sp01 W2 Importer 마무리 + Sp02 재개) 간섭 0 / 차도윤 Sp-W01 킥오프 5/18 간섭 0 |
| 단점 | 외주 검수 부담 + 한가영 0 편차 원칙 검증 외주 인계 부담 |
| 발주 시점 | **5/15 정현우 회신** — D+14 3자 합의 (5/18) 직전 PD 결정 |

### 옵션 B — Self-build (정현우 + 차도윤 ~80h)

| 항목 | 내역 |
|------|------|
| 작업 범위 | 정현우 ~50h (CI/CD + Unity export) + 차도윤 ~30h (Phaser 임베드 + 모노레포 통합) |
| 일정 | Sp-W01 (5/18~5/31) 14h + Sp-W02 (6/1~6/14) 14h × 2주 정현우 분산 |
| 장점 | 외주 검수 0 / 한가영 검증 라인 인하우스 / 향후 유지보수 용이 |
| 단점 | 정현우 Sp02 재개 (9/15) 일정 1~2주 지연 위험 / 차도윤 Sp-W01~W02 30h 추가 |
| 발주 시점 | D+14 (5/18) 합의 후 즉시 |

**정현우 권장**: 본인 의견은 **옵션 B (Self-build) 약간 우세**. 사유 — 한가영 0 편차 원칙 검증 라인이 외주 인계 가능 단계가 아님 + 모노레포 `packages/shared` 가 김민준·차도윤 공동 소유라 외주 갱신 권한 모호. 단 PD 결정 우선.
