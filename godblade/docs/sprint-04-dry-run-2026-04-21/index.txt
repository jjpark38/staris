### §0.2 최상위 리스크 3건

1. **R-DR-10 [High · 3 스택정책 switch/enum 4종 누락]** — README §3.2 는 4가지 `stack_policy` 값(`additive_crossAxis` / `additive_hardcap` / `exclusive_onlyOne` / `additive`) 정의. Calculator 확장 시 `switch(policy)` 에서 한 case 누락되면 **default fall-through → `additive_crossAxis` 로 처리 → `exclusive_onlyOne` 대상 6개 스탯(DropRatePct/GoldGainPct/ExpGainPct/IdleYieldPct/PpGainPct/EquipOptionAmp)이 프레스티지+어픽스 이중 덧셈**. README §3.1 예시대로 `IdleYieldPct` 가 1.345배가 아닌 3.31배 방치 드립 폭주. **감지 방법**: Unknown policy는 Fail-loud (`throw new InvalidEnumArgumentException`)로 강제. README §6-2 "Unknown policy 는 Fail-loud" 규약 준수 여부가 PR 리뷰 체크포인트. Edit Mode 테스트 #07 B10 경제특화 빌드(2.73x) 가 이중 적립 시 ~4.5x로 점프 → 자기검증 ±5% 이탈 Red.

2. **R-DR-11 [High · Mythic 재롤 50PP 차감 경로 `PlayerPrestigeState.AddPermanentPp(-50)` 시그니처 drift 가능성]** — Sp02 W2 `AddPermanentPp(long)` / `AddSeasonalPp(long)` 는 적립 전용 목적으로 설계됨(README d8 §3 Sp02 W2 스케치). **음수 차감을 허용하는지 실측 미검증**. Sp02 W2 내부 구현에 `Assert.IsTrue(amount >= 0)` 가드가 있을 경우 Mythic 재롤 시 `AddPermanentPp(-50)` 호출 = 런타임 Assertion Failure → Sp04 범위 내 재롤 시스템 전체 블록. **부분 FP 가능성**: Sp03 R-DR-09 와 동일 패턴. Sp02 W2 APPROVED 문서 [sprint-02-w2-prestige-tech-sketch.md:193-194] `public void AddPermanentPp(long)` 시그니처 존재는 확인됨. 단 음수 처리 정책은 설계 문서에 명시 안 됨 → **사전 완화 B1: 2026-07-12 D-1에 Sp02 W2 실 PR에서 음수 처리 로직(가드 throw / clamp 0 / 정상 차감) 실측 필수**. 없으면 Sp04 범위에 `SpendPermanentPp(long amount)` 별도 메서드 신설 0.5h 추가.

## §2. #04 StackPolicy enum + Calculator 확장 Phase 분해

> R-DR-10 직결 — Sp04 최대 리스크.

### §2.1 Phase 구조

**Phase A (enum + 수식 1 policy)**: `StackPolicy.AdditiveCrossAxis` 1종 구현 (README §3.3 수식의 else 브랜치) — Sp02 W2 기존 `CalcMultiplier(key, prestigeLv)` 오버로드로 `CalcMultiplier(key, prestigeLv, affixSumPct)` 신설. 기존 시그니처 불변 (Sp02 W2 APPROVED 결정 준수). 30분.

**Phase B (4 policy 분기 switch)**: `switch(policy)` 4 case + `default: throw new InvalidEnumArgumentException($"Unknown StackPolicy: {policy}")`. README §3.3 수식 정확 인용: `additive_hardcap` 시 `1 + Math.Min(hardcap[stat], prestige + affixSum)`. 45분.

**Phase C (hardcap 7 스탯 테이블)**: `StatHardcapTable` 정적 클래스에 CritRate 100% / Dodge 40% / Cooldown 80% / DamageReduction 60% / AttackSpeed 100% / MoveSpeed 30% / LifeSteal 15% 상수 7개 하드코딩. README §3.2 정확 인용. 30분.

**Phase D (exclusive_onlyOne 로직)**: `1 + Math.Max(prestige, affixSum)` — 6 스탯 대상. 단순하나 음수 시 `Max(-0.1, 0.3) = 0.3` 보장 확인. 15분.

### §2.2 위험 포인트

- **switch fall-through**: C# 은 case 사이 fall-through 금지(break/return 필수)라 언어 차원 가드. 단 **한 case 누락** 시 default 로 흘러 throw → #07 자기검증에서 즉시 Red. 의도된 감지.
- **`affixSumPct` 타입 혼란**: `affixSumPct = 0.24f` 는 24% 를 의미. Calculator 내부에서 `1 + sumPct` 형식 유지. Sp02 W1 프레스티지 30항목과 동일 규약.
- **hardcap 초과 시 silent clamp vs warn**: README §3.3 은 `min(hardcap, sum)` 으로 silent clamp. 단 CritRate 누적 110% 시 `Debug.LogWarning` 여부 미정 — 드라이런 범위 외 (Sp05+ 세부 튜닝).

## §3. #05 AffixRoller 가중치 추첨 Phase 분해
