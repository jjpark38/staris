# FlatBuffer 3자 합의 D+2 사전 자료 — 정현우 50h 분배 1차안

## §1 정현우 50h Self-build 분배 1차안 (5단계 PoC 스케치)

| # | 단계 | 공수 | Sp-W 분산 | 산출물 |
|---|------|-----|---------|------|
| 1 | **flatc 환경 셋업 + .fbs 표준화** | 8h | Sp-W01 (5/18~5/24) | `tools/flatc/` + 컨벤션 1쪽 |
| 2 | **GitHub Actions auto-gen 워크플로우** | 10h | Sp-W01~W02 (5/18~6/01) | `.github/workflows/flatbuffer-gen.yml` (TSV commit → .fbs → C#/JS gen → 회귀 테스트) |
| 3 | **Unity Editor batch script + Addressables 정합** | 14h | Sp-W02~W03 (5/25~6/15) | `Unity6/Assets/Editor/FlatBufferImporter.cs` + `.bytes` AssetReference + Label |
| 4 | **Datasheets/TSV → .fbs 변환 파이프라인 (Layer 3a Unity SO export)** | 12h | Sp-W03~W04 (6/08~6/29) | TSV → .fbs (35어픽스 + 30프레스티지 + 전직 트리 등 v1.1 IP 정합) → SO 빌드타임 변환 |
| 5 | **200F 4.255 baseline 회귀 hook 통합 (한가영 라인 sync)** | 6h | Sp-W04 (6/22~6/29) | 자동 검증 hook + 0.5% 초과 시 즉시 PD·박세린 알림 |
| | **합계** | **50h** | **Sp-W01~W04 6주, ~8.3h/주** | 5 산출물 |

**압축 평가** (DNA §3 — 1주 압축 default):
- 50h / 6h/주 = ~8.3주 → 압축 시도 = **24h 모드 시 5주 (10h/주) 가능**, 단 Sp-W01~W04 웹게임 트랙 부분 협업 (R-V3-1 헷지) 영향 없음 baseline 우선 → **현 8주 분산 유지 권고** (압축 시 200F baseline 회귀 가드 약화 위험).
- 합의 항목: D+2 회의에서 차도윤 30h + 한가영 검증 슬롯 sync 후 최종 8주 vs 5주 결정.

## §2 5/6 (D+2) 3자 합의 회의 어젠다 (90분)

| 시간 | 항목 | 담당 | 산출물 |
|------|-----|------|------|
| 0~10' | 압축 GO 배경 + DNA baseline 공유 | 정현우 (본 자료) | 본 1쪽 |
| 10~25' | **정현우 50h 분배 발표** (§1) | 정현우 | 5단계 PoC 스케치 |
| 25~40' | **차도윤 30h Web 측 분배 발표** | 차도윤 | Vite + Phaser embed PoC + JS 디코더 1쪽 (사전 자료 발주 라인 §4) |
| 40~55' | **한가영 흡수 검증 평가 발표** | 한가영 | 200F 4.255 baseline 회귀 hook + 35어픽스+30프레스티지 sync 1쪽 |
| 55~75' | **3자 합의 5건 락인** (FlatBuffer 잠금 메모리 §3 5건 그대로) | 3자 | 합의안 v1.0 |
| 75~85' | 위험 가정 3건 sync (flatc 학습곡선 / GitHub Actions 비용 / D+10 모노레포 sync) | 3자 | 헷지 라인 |
| 85~90' | **메인 세션 통합 PD 보고 1쪽 양식 합의** | 박세린(PM) 옵저버 | 1쪽 회의록 양식 |

**합의 5건 (FlatBuffer 잠금 메모리 §3 그대로 적용)**:
1. .fbs 스키마 표준화 (Datasheets/TSV → .fbs 변환 컨벤션)
2. GitHub Actions 자동 빌드 (TSV commit → gen → 회귀 테스트)
3. Unity Editor batch script (Layer 3a, 정현우)
4. Web (Vite + Phaser) embed (Layer 3b, 차도윤)
5. 200F 4.255 baseline 회귀 검증 (한가영 주 1회 자동)

## §3 PD 답 슬롯: **0건** (자율 default 잠금)

- D+2 회의 결과는 메인 세션 통합 → PD 1쪽 보고
- 압축 GO + R2/R3/R4 default 일괄 채택 = PD 직접 결정 0
- D+2 합의 후 즉시 Sp-W01 (5/18) 진입 가능 (모노레포 D+10 게이트 PASS 가정)

## §4 차도윤·한가영 발주 라인 (메인 세션 처리)

### 차도윤 (web-game-lead, 30h)
- 본 §1 정현우 50h 분배 인용 + Web 측 30h 분배 1차안 작성
- 5단계 sync: (1) JS 디코더 환경 / (2) Vite 통합 / (3) Phaser embed PoC / (4) JSON embed (Layer 3b) / (5) 모노레포 packages/shared 공동 소유
- 산출물: `designs/flatbuffer_3way_web_d_plus_2_pre.md` (D+2 회의 전 1쪽)

### 한가영 (web-game-balance, 흡수 검증 슬롯)
- 본 §1 정현우 분배 §1.5 (200F baseline hook 6h) 인용
- 35어픽스 + 30프레스티지 + 200F 4.255 baseline 회귀 검증 hook 평가
- 산출물: `designs/flatbuffer_3way_balance_d_plus_2_pre.md` (D+2 회의 전 1쪽)

## §5 박세린(PM) 알림 압축 (5/17 → 5/5)

- **기존**: D+13 (5/17) 박세린 PM 모노레포 D+10 게이트 PASS 알림 → D+14 (5/18) 3자 합의
- **압축 후**: **D+1 (5/5 오늘)** 박세린 PM 알림 = "FlatBuffer 3자 합의 D+14 → D+2 압축 / 모노레포 D+10 → D+1 게이트 사전 평가 필요"
- 박세린 PM 일정 baseline 영향 = §6 별도 (메인 세션 통합 처리)

## §6 위험 가정 3건 (FlatBuffer 잠금 메모리 §위험 그대로)

1. **flatc 학습 곡선** — 정현우 첫 도입. 헷지 = D+1 (5/5 오늘) 1h 사전 학습 (PoC 1h)
2. **GitHub Actions 비용** — 5~10분/회 × 월 100회 가정 = 무료 tier 내. 헷지 = D+30 실측
3. **D+2 압축 = 모노레포 D+10 게이트 사전 PASS 의존** — 압축 시 모노레포 PR merge 미완 가능. 헷지 = D+2 회의에서 모노레포 상태 확인 후 합의 락인 vs 일정 슬립 결정
