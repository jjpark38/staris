## §3 `IdleCapHoursFlat` 특수 경로 스펙

### §3.1 왜 특수 경로인가

`IdleCapHoursFlat` (item_id=25) 은 30개 중 유일하게 **"시간(h) 절대값"** 을 나타내는 FlatStat 타입. 나머지 PercentStat 29개는 전부 `1 + Σ(level × per_level × diminish)` 식 곱연산 멀티플라이어로 집계되지만, `IdleCapHours` 는 다음 이유로 별도 경로 필수:

1. **단위 불일치**: PercentStat은 비율(dimensionless), FlatStat은 시간(hours). 같은 스칼라 필드에 곱연산으로 집계 불가.
2. **수식 역할 다름**: 곱연산 필드는 "보너스 배수" 로 피해·보상에 곱해지지만, `IdleCapHours` 는 "오프라인 계산 상한" 으로 `min()` 연산의 입력.
3. **소프트캡 동작 다름**: PercentStat은 `Lv > 5` 시 log diminishing, FlatStat 25번은 `FlatSteps` 곡선 — **Lv 1~5 선형 (+2h/레벨), 이후 투자 불가(하드캡)**. Sprint 02 W1 `prestige_items_README.md` 메모리 합의에서 "CapBehavior=Block UI" 로 확정.

### §3.2 집계 수식

TSV 값:
- `base_value = 24` (기본 캡 24h)
- `per_level_value = 2` (레벨당 +2h)
- `softcap_level = 5` (하드캡)
- `post_softcap_diminish = 0.00` (Lv 6+ 투자 불가)

```
level = PrestigeCalculator.CalculateLevel(state.GetPpInvested(item_id=25), softCap=5)
level_clamped = min(level, 5)   // FlatSteps 하드캡
idleCapHours  = 24 + 2 × level_clamped
             = Lv0: 24h / Lv1: 26h / Lv2: 28h / Lv3: 30h / Lv4: 32h / Lv5: 34h
```

### §3.3 Sprint 02 W2 `PrestigeCalculator` 구현 요구사항

```
// 신규 헬퍼 (Sprint 03 리서치 §5 축8 에서 이미 예고됨 — "GetIdleCapHours(state) 신규")
public static int GetIdleCapHours(in PlayerPrestigeState state) {
    int pp     = state.GetPpInvested(stat_key: "IdleCapHoursFlat");
    int level  = CalculateLevel(pp, softCap: 5);
    int capped = math.min(level, 5);
    return 24 + 2 * capped;   // base + per_level × level (Flat 가산)
}
```

- **불변 원칙**: `PrestigeCalculator.CalculateLevel(int pp, byte softCap)` 시그니처는 메모리 합의대로 고정. 신규 `GetIdleCapHours` 는 **헬퍼 메서드 추가 = 시그니처 변경 아님 = OK** (Sprint 03 리서치 §5 축8 재확인과 일치).
- `BuildSummary` 에 `IdleCapHours` 필드를 포함할지 vs 별도 헬퍼 호출할지는 code-lead 판단. 본 문서는 "별도 경로 처리"만 명시.

### §3.4 Sprint 03 `IdleRewardCalculator` 호출 패턴
