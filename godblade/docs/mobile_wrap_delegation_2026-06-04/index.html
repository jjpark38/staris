3. 위임 사유 2건

사유 1 — 차도윤 페르소나 약점 (모바일 광고 SDK 0 경험)

.claude/agents/web-game-lead.md L26~31 명시:

모바일 네이티브 광고 SDK 0 경험 — IronSource / AppLovin 모바일 광고는 류재현(dots-platform) 의존. 웹 광고는 본인 처리 (AdSense / Coinis).

차도윤(차도윤 가정 인용): "현우님, 모바일 wrap 자체보다 광고 SDK 통합이 발목 잡습니다. IronSource Capacitor plugin 자체 PoC 1주 + AppLovin MAX 통합 1주 + 양 OS 정책 검수 1~2주 — 도합 4주 추정인데 저는 0 경험입니다. 류재현님 SDK 본체 + 현우님 wrap 통합 라인이 본인 학습 4주 비용 회피입니다."

사유 2 — 정현우 영역 시너지 (Steam Electron + 모바일 wrap = 1 영역)

정현우 영역에 이미 Steam Electron 빌드 파이프라인이 박혀 있음. 모바일 wrap (Capacitor / Cordova) 도 동일 패턴 — 네이티브 wrap + 빌드 서명 + 스토어 제출. 차도윤이 별도 학습 4주 들이는 것보다 정현우 영역에 합쳐서 1 영역 통합이 학습 비용 0 + 빌드 파이프라인 일관성 확보.

정현우 본인 발화: "Steam Electron 이미 셋업했으니 Capacitor 추가 1~2주면 됩니다. 단 광고 SDK 통합은 류재현님 본체 의존 — 본인은 wrap layer 만."

5. 차도윤 잔여 영역 (D+30 이후)

  • 웹 PWA 매니페스트 (webgame/public/manifest.json)
  • Service Worker (오프라인 캐시 + Phaser asset preload)
  • 모바일 브라우저 60fps (iOS Safari / Android Chrome — 임재훈 60fps 부하 테스트 협업)
  • 웹 광고 (AdSense / Coinis) — 웹 PWA 한정, 모바일 native 광고 위임
  • 모바일 브라우저 입력 (touch event) — Phaser 3 input plugin 활용
  • Firestore 세이브 sync (모바일 브라우저까지)

6. 정현우 신규 영역 (D+30 이후, Sp02 재개 후 = 2026-09-15+)

  • Capacitor 또는 Cordova 셋업 — Capacitor 우선 권장 (Ionic 표준 / Phaser 3 호환 검증 사례 다수)
  • iOS 빌드 파이프라인 — Xcode + 인증서 + TestFlight + App Store Connect
  • Android 빌드 파이프라인 — Gradle + Keystore + Play Console
  • 모바일 광고 SDK Capacitor plugin layer — 류재현 본체 SDK wrap, JS 인터페이스 차도윤에게 노출
  • App Store / Play Store 제출 자동화 — GitHub Actions 또는 fastlane

7. 위험 가정 2건

  1. 차도윤 모바일 브라우저 60fps 미달 시 native wrap 우회 압력 → 헷지: 임재훈 부하 테스트 (Sp-W02 6/1) 60fps 검증 통과 시 native wrap 일정 D+30 유지. 미달 시 정현우 영역 합류 시점 앞당김 (Sp-W04 6/29 검토) + PD 보고
  2. 류재현 광고 SDK 본체 작업 일정 미정 → 헷지: 본 합의는 wrap layer 합의만. 류재현 본체 일정은 dots-platform agent 별도 발주 (정현우 + 류재현 D+45 1:1 추가 합의 예약)
