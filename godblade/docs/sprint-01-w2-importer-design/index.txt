### 1.2 권장안 = 옵션 A + DOTS 스키마 사전 호환

- **A 채택** 이유: Sprint 00 `TranscendentStageCatalogSO` → Importer → Addressables 경로가 이미 검증됨(2건 회귀 포함). 같은 패턴 3회 복제가 가장 싼 길.
- **DOTS 호환 배려**: `DropRateRow` 같은 row 타입을 `[System.Serializable] struct`로 잡고 모든 필드 `blittable`(int/enum/float)로 유지 → Sprint 02+ `BlobArray<DropRateRow>`로 **이사 가능** (SO → Blob 전환 시 필드 매핑 1:1).
- **무엇을 하지 않는가**: Grade 리매핑 결과까지 저장 (런타임 enum은 신규 6등급만, 원본 4등급은 Importer가 변환 후 버림).

## 2. Importer 클래스 설계

### 2.1 파일 레이아웃 (전부 Editor 어셈블리)

```

      GradeParser.cs                                    (신규, "Rare"→Grade.Rare(신규 Epic 의미 NOT 원본!))
```

### 2.2 ScriptedImporter vs MenuItem — **MenuItem 채택**

- Sprint 00 `TranscendentStageImporter`가 `[MenuItem]` 방식 검증 완료. 단일 패턴 유지.
- ScriptedImporter는 TSV가 Assets/ 내부에 놓여야 함. 본 프로젝트 TSV는 `designs/` 폴더(저장소 루트, Unity 프로젝트 외부). 이식 비용 없음.
- 대신 메뉴 4개로 엔지니어 선택권 제공:
  - `GodBlade/Data/Import Transcendent Stage TSV` (Sprint 00 기존)
  - `GodBlade/Data/Import Drop Rate Table TSV` (신규)
  - `GodBlade/Data/Import Milestone Reward TSV` (신규)
  - `GodBlade/Data/Import Affix Pool TSV` (신규)
  - `GodBlade/Data/Import ALL (Stage → Drop → Milestone → Affix)` (신규, 의존 순서 보장)

### 2.3 의존 순서 = `Import ALL` 한 진입점이 보장

```
[1] TranscendentStageImporter.Import()   (Sprint 00)     — Stage SO 200개 + Catalog
[2] DropRateTableImporter.Import()                       — Stage에 의존하지 않음(독립)
[3] MilestoneRewardImporter.Import()                     — floor→Stage FK 없음(Grant 시 lookup)
[4] AffixPoolImporter.Import()                           — 독립
```

- 실제로 Stage SO에 대한 **컴파일 타임 의존은 없음**(보상 TSV는 floor만 들고 있음). 런타임 Granter가 catalog.GetByFloor()로 조회.
- 따라서 순서 강제는 "안전 마진"일 뿐. 메뉴로 개별 실행도 무방.

### 2.4 공통 Const 규약 (Sprint 00과 동일 룩&필)

- Sprint 00 `TranscendentStageImporter` 내부 `Row` / `ReadTsv` / `ValidateHeader` 3개를 `Shared/TsvReader.cs` 로 **추출**.
- Sprint 00 Importer는 동작 불변 — 새 공통 모듈을 호출하도록 **최소 편집** (Sprint 00 검증 자산 파괴 금지).

## 3. Grade 리매핑 (CP1 대응)

### 3.1 위치 = `GodBlade.Data` 어셈블리 (`Assets/_Project/Scripts/Data/GradeRemap.cs`)

- 이유: `Grade` enum은 런타임 전역 표준. Runtime·Editor·Data 모두 참조.
- `GodBlade.Data.asmdef` 는 `references: []` 빈 배열 유지 가능(의존 없음).

### 3.2 Enum 구조 초안

```csharp
namespace GodBlade.Data {
  public enum Grade {
    Common     = 0,   // 원본 Normal
    Magic      = 1,   // 신규 (원본 없음, Sprint 02 Normal 복제)
    Rare       = 2,   // 원본 Superior  ← ★ 의미 변경 주의
    Epic       = 3,   // 원본 Rare      ← ★ 절대 혼동 금지
    Legendary  = 4,   // 원본 Unique
    Mythic     = 5,   // 신규 (원본 없음)
  }

  public enum MobKind { Normal = 0, Boss = 1 }

  public enum RewardType {
    CurrencyGold,
    EquipmentRandom,
    AffixRerollToken,
    GuardianExp,
    GuardianStone,
    CosmeticTitle,
    CosmeticAura,
    Unknown,
  }

  public static class GradeRemap {
    // 원본 XML Grade 리터럴 4종 → 신규 enum
    // Sprint 01 W2: TSV 내부 리터럴(신규 6종) 직접 파싱 + 이 맵은 Sprint 02 XML 주입 때 쓰임
    public static bool TryFromLegacy(string legacyLiteral, out Grade grade) { ... }

    // TSV 내부 신규 리터럴 파싱
    public static bool TryParseNew(string literal, out Grade grade) { ... }
  }

  public sealed class UnknownGradeException : System.Exception {
    public string Literal { get; }
    public string SourceTsv { get; }
    public int RowNumber { get; }
  }
}
```

### 3.3 리매핑 테이블 (하드코딩, Dictionary)

| 원본 리터럴(XML, Sprint 02 주입용) | 신규 Grade | 주의 |
|------|------|------|
| `"Normal"`    | `Grade.Common`    | 1:1 |
| `"Superior"`  | `Grade.Rare`      | 상향 1단계 |
| `"Rare"`      | `Grade.Epic`      | ★ 원본 Rare ≠ 신규 Rare. **코멘트 3줄** 필수 |
| `"Unique"`    | `Grade.Legendary` | 1:1 |
| 그 외(`"Magic"`/`"Mythic"`/대소문자 변형/오타) | **`UnknownGradeException`** 발생 |

### 3.4 Unknown 정책

- Importer는 Row 단위로 try/catch 하지 **않음**. 첫 Unknown 만나면 즉시 `UnknownGradeException` throw → Importer 중단 + `EditorUtility.DisplayDialog` + 콘솔 Error.
- 이유: 조용한 0 채움(Sprint 00에서 BOM으로 한 번 당했음)보다 "큰 소리로 실패"가 낫다. PD 일관 방침.
- `Literal`, `SourceTsv`, `RowNumber` 세 필드 포함 → 엔지니어가 10초 안에 수정 위치 파악.

## 4. 드롭 테이블 Lookup (CP2·CP3 대응)

### 4.1 자료구조 = `Dictionary<Key, float>`

```csharp
readonly struct DropRateKey : System.IEquatable<DropRateKey> {
  public readonly byte BucketId;   // 0~4, 5개 버킷 (1-30, 31-80, 81-130, 131-180, 181-200)
  public readonly byte MobKind;    // Normal=0 / Boss=1
  public readonly byte Grade;      // 0~5
  // GetHashCode = BucketId | (MobKind<<4) | (Grade<<5)  → 컴팩트
  public bool Equals(DropRateKey o) => ...
}

Dictionary<DropRateKey, float> _lookup   // 60 엔트리 (5×2×6)
```

### 4.2 왜 Dictionary인가 (vs 다차원 배열)

| 접근 | Dictionary | `float[5,2,6]` |
|------|-----------|----------------|
| 조회 O(1) | 해시 + EqualityComparer | 직접 인덱싱 (더 빠름) |
| 누락 검증 | `TryGetValue` false → 0 감지 쉬움 | 0.0 가 "미정"인지 "진짜 0"인지 모호 |
| 직렬화 | SO에는 `List<DropRateRow>` 저장, OnEnable에서 Dictionary 빌드 | 다차원 배열은 Unity 직렬화 불가 → 래핑 필요 |
| 확장 | mobKind 추가 쉬움 | 상수 5/2/6 고정 — 추가 시 리팩터 |

**선택: Dictionary + OnEnable lazy build** (Sprint 00 `TranscendentStageCatalogSO._byCode` 패턴 그대로).

### 4.3 Floor → BucketId 변환 (CP3 경계값)

```csharp
static byte FloorToBucket(int floor) {
  if (floor <=  30) return 0;
  if (floor <=  80) return 1;
  if (floor <= 130) return 2;
  if (floor <= 180) return 3;
  return 4;  // 181~200
}
```

- 이분 탐색 불필요 — 버킷 5개. 상수 분기가 캐시·분기예측에 최선.
- 경계 규칙: `min <= floor <= max` (양끝 포함) — Sprint 01 W1 README §6-CP3 과 일치.
- `DropRateRow.floorMin` / `floorMax` 는 **검증용**으로만 저장 (런타임 조회는 BucketId만 씀). 불변성 자기검증 로그로 활용.

### 4.4 런타임 API 초안 (`DropRateTableSO` 메서드)

```csharp
public float GetDropRate(int floor, MobKind mob, Grade grade);
// floor 1~200 → BucketId → key → dict. miss면 0.0 + Debug.LogWarning(한 번만).

public Grade RollGrade(int floor, MobKind mob, System.Random rng);
// 6등급 weighted pick. 내부에서 GetDropRate 6회 + 누적분포 생성 (캐시 고려는 Sprint 02 측정 후).
```

### 4.5 드롭률 합 자기검증 (Importer)

- Import 끝에서 **5개 버킷 × 2개 mobKind = 10개 합**을 계산.
- `|sum - 1.000| > 0.001` → `Debug.LogError` + `Dialog` (런타임 Crash 금지, Editor 전용 Alert).
- 로그 포맷: `[DropRateTableImporter] SUM ERROR bucket=81-130 mob=Normal sum=0.9997 expected=1.000`

## 5. TBD_ 플레이스홀더 처리 (CP4)

### 5.1 감지

- `MilestoneRewardRow.rewardCode` 가 `string` 타입. `reward_code` 컬럼이 `1`(정수 문자열), `TBD_EQUIP_POOL`, `TBD_REROLL`, `TBD_TITLE_100` 등 혼재.
- Importer가 prefix 검사:
  ```
  bool isPlaceholder = rewardCode.StartsWith("TBD_", StringComparison.Ordinal);
  ```
- 현재 TSV 22행 중 `TBD_*` = 14행 (필수 Skip 아님, **표시**만 함).

### 5.2 정책 = **로드는 하되 런타임 Grant는 Skip + Warn**

- Import 단계: 모든 row를 SO에 저장 (placeholder 포함). 데이터 손실 없음.
- 런타임 `MilestoneGranter.Award(floor)` 내부에서 row.IsPlaceholder = true면:
  ```
  Debug.LogWarning($"[MilestoneGranter] TBD reward skipped: floor={floor} code={rewardCode}");
  continue;  // 다음 row 진행
  ```
- 이유: Sprint 02에서 `ItemInfo.xml` 매핑 완료되면 TSV만 갱신 + Importer 재실행하면 자동 활성. 코드 변경 0.

### 5.3 TODO / Issue 스텁

- `MilestoneRewardRow` 구조체에 `public bool IsPlaceholder` 계산 프로퍼티 부착.
- 코드 주석 고정 형식:
  ```
  // TODO(Sprint 02): TBD_EQUIP_POOL → RewardItemInfo.xml StageGeneralCode=5001 계열 매핑
  //                  TBD_REROLL     → 신규 아이템 등록 (game-designer 협업)
  //                  TBD_TITLE_*    → 칭호 시스템 설계 후 (Sprint 04+)
  ```
- PM에게 Sprint 02 킥오프 때 "TBD 14건 치환 과제" 별도 티켓 등록 요청.

### 7.2 API 초안

```csharp
namespace GodBlade.Runtime.Rewards {
  public sealed class MilestoneGranter {
    private readonly MilestoneRewardCatalogSO _catalog;
    public MilestoneGranter(MilestoneRewardCatalogSO catalog) { ... }

    // 드롭 Roll과 독립. FloorReached 이벤트 채널 한 번만 호출.
    public IReadOnlyList<GrantResult> Award(int floor);

    public readonly struct GrantResult {
      public readonly MilestoneRewardRow Row;
      public readonly bool Skipped;             // TBD placeholder면 true
      public readonly string SkipReason;
    }
  }
}
```

### 7.3 로드 시점

- `GodBlade.Runtime` 내 `RewardBootstrap` (미존재, Sprint 01 W2 추가) 이 Addressables에서 3개 SO를 병렬 로드.
- Sprint 00 `SmokeTester`의 `AsyncOperationHandle<T>` 패턴 재사용. 3개 핸들 `WhenAll` 유사 동시 대기.

### 7.4 드롭 Roll과 중복 지급 방지 (이벤트 채널 분리)

```
이벤트 채널 A: OnMonsterKilled(floor, mobKind, monsterCode)
  → LootRoller (드롭 Roll: DropRateTableSO + AffixPoolSO)

이벤트 채널 B: OnFloorReached(floor) ← 층 클리어 1회만 발화
  → MilestoneGranter.Award(floor) ← 10/50/100/150/200에만 실제 지급
```

- 두 채널이 서로 호출하지 않음(결합 없음).
- `MilestoneRewardCatalogSO` 는 floor 키를 Set으로 미리 캐시(`_milestoneFloors`) → `OnFloorReached`가 매번 전체 스캔 안 하도록. 22행이라 성능 이슈 없지만 방어적.

## 9. 정적 분석 한계 + 컴파일러 시뮬레이션 체크리스트

> **PD 명시 요청 섹션**. 2026-04-21 Sprint 00 회귀 2건(CS0246 `ResourceManager` 네임스페이스 누락 / CS1061 멤버 접근 실패)이 정적 리뷰를 통과했지만 실컴파일에서 드러났다. W2 PR 제출 전 다음 **11개 체크 포인트** 를 코드 작성자가 직접 확인한다.

### 9.1 체크 포인트 (11개)

1. **[CP9-1] asmdef references 배열 완결성** — 신규 테스트 asmdef `GodBlade.Tests.Editor.asmdef` 에 다음 누락 재발 금지:
   - `UnityEngine.TestRunner`
   - `UnityEditor.TestRunner`
   - `GodBlade.Data` / `GodBlade.Runtime` / `GodBlade.Editor`
   - (Sprint 00 재발 사례) `Unity.ResourceManager` — Addressables `AsyncOperationHandle<T>` 건드리면 필수
2. **[CP9-2] Editor asmdef의 `Unity.Addressables.Editor` 유지** — 기존 `GodBlade.Editor.asmdef` 은 이미 포함. 신규 Importer들이 `AddressableAssetSettingsDefaultObject` 를 건드리면 이 참조 없으면 CS0246.
3. **[CP9-3] `internal` 멤버 + `[InternalsVisibleTo]`** — 새 SO 중 Editor만 쓸 세터가 있으면 `TranscendentStageSO.cs` 상단의 `[assembly: InternalsVisibleTo("GodBlade.Editor")]` 패턴 복제. 새 SO 파일마다 중복 선언은 **금지** (중복 정의 CS0579). 한 파일에만.
4. **[CP9-4] `#if UNITY_EDITOR` 가드 경계** — Data asmdef는 Editor 전용 심볼 참조 금지. `UnityEditor.*` 사용 블록은 반드시 `#if UNITY_EDITOR` 로 감싸거나 Editor 어셈블리로 이동.
5. **[CP9-5] 신규 네임스페이스 충돌** — `GodBlade.Runtime.Rewards` / `GodBlade.Data.Rewards`(X, 하위 안 만듦) / `GodBlade.EditorTools.Rewards`(X, 평탄 유지) 중 **Runtime만** 하위 네임스페이스 도입. rootNamespace가 `GodBlade.Runtime` 이므로 파일 최상단 `namespace GodBlade.Runtime.Rewards`로 명시. 자동 삽입 방지 위해 asmdef `rootNamespace` 수정 금지.
   > **NOTE (2026-04-21 scaffold sync audit 반영)**: Editor asmdef의 **파일명은 `GodBlade.Editor`** 이나 **rootNamespace / 파일 내 네임스페이스는 `GodBlade.EditorTools`** (Sprint 00 scaffold 컨벤션 유지). 본 문서에서 `GodBlade.Editor.*` 표기는 asmdef **이름** 기준이며, 실제 코드 작성 시 `namespace GodBlade.EditorTools` / `GodBlade.EditorTools.Rewards` 사용. asmdef `rootNamespace` 수정 금지.
6. **[CP9-6] TSV `Split('\t')` CRLF/LF 처리** — `File.ReadAllLines` 는 플랫폼 개행을 자동 분리하나, Windows TSV를 LF만 남기는 편집기에서 복사된 경우 마지막 줄에 `\r` 잔여. Row 파싱 후 `Trim()` 1회:
   ```
   for (int c = 0; c < max; c++) row.Fields[header[c]] = cells[c].Trim();
   ```
   Sprint 00 `TranscendentStageImporter.ReadTsv` 에 없음 — 공통 `TsvReader` 추출 시 함께 보강.
7. **[CP9-7] BOM 트림 중복 적용** — 공통 `TsvReader` 한 곳만 BOM trim. Sprint 00 기존 함수에서 제거(중복 작업 방지 — 단 테스트 돌려 회귀 없음 확인 후 제거).
8. **[CP9-8] Dictionary 직렬화 금지** — Unity는 `Dictionary<K,V>` 직렬화 안 함. SO는 반드시 `List<Row>` 로 저장, `[NonSerialized]` Dictionary는 `OnEnable`에서 빌드. Sprint 00 Catalog 패턴 유지.
9. **[CP9-9] Enum underlying type 고정** — `Grade : int` 기본이지만, DOTS 전환 고려하면 `byte` 로 선언 가능. **W2에서는 int 유지** (Unity Inspector 표시, Serialize compatibility 안정). Sprint 02+ DOTS 전환 시 한 번에 byte로.
10. **[CP9-10] `System.Random` 는 런타임 전용 / Editor Import 단계는 rng 금지** — Importer는 결정론적(input TSV만). rng 사용 zero. `LootRoller`(Sprint 02)에서 도입.
11. **[CP9-11] Addressables 그룹 중복 생성 방지** — 신규 `Rewards` 그룹을 Stage 그룹과 별도로 만들 것. `settings.FindGroup("Rewards")` 로 기존 확인 후 없으면 생성. Sprint 00 `TranscendentStageImporter.RegisterAddressables` 패턴 복제.

### 9.2 Sprint 00 회귀 2건 재발 경고 (반드시 읽기)

- **회귀 A (CS0246)**: Runtime asmdef가 `Unity.ResourceManager` 미참조 → `AsyncOperationHandle<T>` 타입 해석 실패. → **CP9-1, CP9-2 확인 필수**.
- **회귀 B (CS1061)**: Editor 메뉴에서 Data asmdef의 private 세터 호출 → `InternalsVisibleTo` 선언 파일 오타 / 어셈블리 이름 불일치 → **CP9-3 확인 필수**.
- 두 건 모두 정적 리뷰 통과, 실컴파일에서 검출. 본 설계 W2 코드 작성자는 **Unity 에디터 연 상태로 파일 저장 → Console 새 에러 0 확인 후 PR 올림**.
