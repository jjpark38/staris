## 1. 데이터 모델 선택

### 1.1 전제: 슬롯 수 × 상태 성격

- **슬롯 수**: 30항목 × 2채널 = **유저 1인당 60 슬롯**.
- **성격**: 투자·회수·리스펙 빈도 높음. Read-mostly가 아니라 **read-write hot path**.
- Sprint 01 W2 `DropRateTableSO` / `MilestoneRewardCatalogSO` 는 **read-only 카탈로그** → SO 적합. 프레스티지 상태는 **유저 세이브** → SO 적합도 낮음.

### 1.2 3옵션 비교

| 옵션 | 구조 | 장점 | 단점 | Sprint 02 적합성 |
|------|------|------|------|---------|
| **A. 단일 SO 60필드** | `PlayerPrestigeStateSO` 에 `permanent_00` ~ `permanent_29`, `seasonal_00` ~ `seasonal_29` 필드 60개 | Sprint 01 W2 SO 패턴 1:1 | 필드 60개 직렬화 노이즈 / 항목 추가 시 재컴파일 / 리플렉션 없이 인덱서 불가 | ❌ |
| **B. Struct + List (권장)** | `PrestigeSlot` struct 60개를 `List<PrestigeSlot>` 에 평탄 저장 + `(channel, itemId)` 인덱서 | blittable struct → DOTS 전환 친화 / JSON 직렬화 자연 / 항목 확장 무공사 | SO 아님 → `ScriptableObject`가 아닌 POCO. 별도 저장 파이프 필요 | **✅ 권장** |
| **C. ECS `IComponentData` + `DynamicBuffer<PrestigePointSlot>`** | DOTS 네이티브 | 수십만 유저 시뮬 시 캐시 친화 | 싱글 플레이어(유저 1명) / Sprint 02 범위 과도 / Conversion Workflow 도입 비용 | ❌ Sprint 03+ 측정 후 재검토 |

### 1.3 권장 = 옵션 B

```csharp
// GodBlade.Runtime — Assets/_Project/Scripts/Runtime/Prestige/PrestigeSlot.cs
namespace GodBlade.Runtime.Prestige {
  public enum PpChannel : byte {
    Permanent = 0,
    Seasonal  = 1,
  }

  [System.Serializable]
  public struct PrestigeSlot : System.IEquatable<PrestigeSlot> {
    public ushort itemId;       // PrestigeItemCatalogSO 의 row index (0~29)
    public PpChannel channel;   // 1 byte
    public int investedPp;      // 누적 투자 PP (회수 시 감소)
    // Level·Bonus 는 저장하지 않음 — PrestigeCalculator 가 실시간 산출 (카탈로그 공식 변경 시 재컴파일 대응)
  }
}
```

- `PrestigeSlot` 은 **blittable** (`byte` + `ushort` + `int`) → Sprint 03 DOTS 전환 시 `IComponentData` 로 1:1 이식 가능.
- 저장 엔티티는 아래(§3)의 `PlayerPrestigeState` 한 클래스가 소유.

### 1.4 Sprint 01 W2 DQ1(SO 옵션 A)과의 관계

- **다른 축**: Sprint 01 W2 DQ1의 "SO 옵션 A"는 **카탈로그**(정적 정의) 저장 방식 결정. 본 문서의 "옵션 A/B/C"는 **유저 런타임 상태** 저장 방식 결정.
- 프레스티지도 **카탈로그(§2)는 Sprint 01 W2 DQ1과 동일하게 SO 옵션 A** 유지 → 일관성 확보.

## 4. PP 슬롯 2채널 구조 (Q3 핵심)

### 4.1 설계 목표

- Sprint 02~04 기간: `Seasonal` 채널은 **UI에서 잠금 표시**(탭 노출 자체 금지 또는 회색 처리). `AddSeasonalPp` 는 호출 가능하지만 트리거 경로 없음 → 실질적으로 0 유지.
- Sprint 05 시점: `SeasonSystem` 신설 → `OnSeasonEnd` 이벤트가 `MigrateSeasonalToPermanent(0.5f)` 호출. 본 W2에서는 **메서드 시그니처만 존재**, 호출자 없음.

### 4.2 채널 경계 불변식

```
불변식 I1: IsUnlocked == false 이면 Slots.Count == 0
불변식 I2: Σ(slot.investedPp where channel=Permanent) ≤ PermanentPp
불변식 I3: Σ(slot.investedPp where channel=Seasonal)  ≤ SeasonalPp
불변식 I4: Sprint 02~04 기간 SeasonalPp == 0 이고 Seasonal 채널 슬롯 없음
불변식 I5: MigrateSeasonalToPermanent 후 SeasonalPp == 0, Seasonal 슬롯 모두 Refund → Permanent Pp 풀로 편입 (비율 적용)
```

- 테스트(§7)에서 I1~I5 모두 검증.

### 4.3 마이그레이션 알고리즘 (의사코드)

```
MigrateSeasonalToPermanent(retainRatio=0.5):
  // Step 1: Seasonal 슬롯 전부 회수 (invested pp 모음)
  seasonalInvested = Σ slot.investedPp where channel=Seasonal
  totalPool = SeasonalPp + seasonalInvested   // 미투자 + 투자 모두
  RemoveAll(s => s.channel == Seasonal)

  // Step 2: retainRatio 적용하여 Permanent Pp 풀에 적립
  converted = floor(totalPool * retainRatio)
  PermanentPp += converted
  SeasonalPp = 0

  // Step 3: 이벤트 발화 (UI 갱신)
  OnPpChanged(Permanent, PermanentPp)
  OnPpChanged(Seasonal, 0)
```

- `retainRatio` 인자화 → Sprint 05 시점에 PD가 비율 조정 가능 (기본 0.5 = 스펙 Q3).
- 부동소수 누적 오차 방지: `long * float` 대신 `long * numerator / denominator` 정수 연산 고려(Sprint 05 재검토).

## 5. 저장·직렬화

### 5.1 저장 방식 비교

| 방식 | 장점 | 단점 | Sprint 02 적합 |
|------|------|------|---------|
| **JSON (Unity `JsonUtility`)** | 사람이 읽기 쉬움 / 디버그 / 스키마 버전 필드 자연 | `Dictionary` 미지원(이미 List 구조) / long 직렬화 OK | **✅** |
| Binary (`BinaryFormatter`) | 크기 작음 | .NET 공식 권장 중단 / 디버그 어려움 | ❌ |
| PlayerPrefs | 편의성 | 60 슬롯·long 값에 부적합 / 문자열 크기 제한 | ❌ |

### 5.2 권장 = JSON + `schemaVersion` 필드

```csharp
namespace GodBlade.Runtime.Prestige {
  [System.Serializable]
  public struct PrestigeSaveDto {
    public int schemaVersion;    // 현재 1. 구조 변경 시 증가.
    public bool isUnlocked;
    public long permanentPp;
    public long seasonalPp;
    public List<PrestigeSlot> slots;
    public long savedAtUnixMs;   // 역산·디버그용
  }

  public static class PrestigeSaveService {
    public const int CURRENT_SCHEMA = 1;

    public static void Save(PlayerPrestigeState state, string accountId);
    public static PlayerPrestigeState Load(string accountId); // 파일 없으면 새 상태 반환
    public static PlayerPrestigeState Migrate(PrestigeSaveDto dto);
      // schemaVersion < CURRENT_SCHEMA → 순차 마이그레이션 훅
      // schemaVersion > CURRENT_SCHEMA → 버전 불일치 경고 + 백업 + 신규 초기화
  }
}
```

### 5.3 저장 경로

```
Application.persistentDataPath/
  account/
    <accountId>/
      prestige.v1.json         ← 현 Sprint 02
      prestige.v1.json.bak     ← 매 저장 전 이전 파일 백업 (마이그레이션 실패 대비)
```

- `accountId` 는 현재 싱글 계정 전제 = `"local"` 고정. Phase 5 Firebase 도입 시 Firebase UID 치환.
- **계정 영구 (Q2)**: 캐릭터 교체·삭제해도 `account/<accountId>/prestige.v1.json` 이 남음 → 진전 보존.
- 멀티 캐릭터 도입 시점에도 경로는 `account/` 하위지 `character/` 하위 아님.

### 5.4 마이그레이션 훅 (schemaVersion 1 → 2 시 대비)

```csharp
public static PlayerPrestigeState Migrate(PrestigeSaveDto dto) {
  switch (dto.schemaVersion) {
    case 1: return LoadV1(dto);
    // case 2: return LoadV2(dto);   ← Sprint 05 시즌 스키마 변경 시 추가
    default:
      Debug.LogWarning($"[PrestigeSave] Unknown schemaVersion {dto.schemaVersion}, starting fresh.");
      BackupCurruptFile(dto);
      return new PlayerPrestigeState();
  }
}
```

### 5.5 저장 타이밍

- **즉시 저장**: `Spend` / `RefundAll` / `Unlock` / `MigrateSeasonalToPermanent` 호출 직후.
- **배치 저장**: `AddPermanentPp` / `AddSeasonalPp` 는 1초 디바운스 (방치 드립 초당 다회 호출 대비).

### 6.3 `PrestigePpAccumulator` 스케치

```csharp
namespace GodBlade.Runtime.Prestige {
  public sealed class PrestigePpAccumulator {
    readonly PlayerPrestigeState _state;
    readonly MilestoneRewardCatalogSO _milestone;  // Sprint 01 W2 자산 재활용

    public PrestigePpAccumulator(PlayerPrestigeState state, MilestoneRewardCatalogSO milestone);

    // 이벤트 핸들러 — Sprint 01 W2 이벤트 채널 구독
    public void OnStageCompleted(int floor);             // §3.2 (A) 층 첫 클리어
    public void GrantBossBonus(int floor);                // §3.2 (B) 보스 반복
    public void GrantIdleDrip(long elapsedSec, int maxFloor);  // §3.2 (C) 방치 드립 (Sprint 03 틱커 발화)
    public void GrantMilestone(int floor);                // §3.2 (D) 마일스톤 1회성
    public void GrantDailyQuest();                        // §3.2 (E) 일일/광고 (Sprint 03+)
  }
}
```

- 계산 공식은 `prestige_system_spec.md` §3.2 인용. 계수 하드코딩 대신 `PrestigeItemCatalogSO` 의 형제 SO(`PrestigeGainRatesSO`) 에 TSV 주입 — **Sprint 03+ 확장 여지 남김** (W2 스코프 아님).
- **W2 범위**: `GrantIdleDrip` 은 핸들러 시그니처만. 발화자(`IdleTicker`)는 Sprint 03 방치 시스템에서 구현.

### 6.4 이벤트 채널 분리 (Sprint 01 W2 §7.4 연장)

```
이벤트 채널 A: OnMonsterKilled(floor, mobKind, monsterCode)
  → LootRoller (Sprint 02)
  → PrestigePpAccumulator.GrantBossBonus (mobKind=Boss 시만)   ← 신규 구독

이벤트 채널 B: OnFloorReached(floor)
  → MilestoneGranter.Award (Sprint 01 W2 기존)
  → PrestigePpAccumulator.OnStageCompleted                     ← 신규 구독
  → (floor==100 && !IsUnlocked) → PlayerPrestigeState.Unlock() ← 신규 경로
  → (floor==200) → PrestigePpAccumulator.GrantMilestone(200)   ← 신규 활성화

이벤트 채널 C (신규): OnSeasonEnd
  → PlayerPrestigeState.MigrateSeasonalToPermanent(0.5f)
  → 발화자는 Sprint 05+ SeasonSystem. W2 구독자만 등록.
```

- 기존 채널 A·B 확장만으로 구조 안정. 채널 C는 Sprint 05까지 **정의만** 존재.
