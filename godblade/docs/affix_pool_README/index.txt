<h2 class="mb-3 mt-6 text-[18px] font-semibold text-gold-light">1. 목적 &amp; Sprint 04 스코프</h2>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">1.1 목적</h3>
<p class="mb-3 text-text-0">Sprint 04 (2026-07-13~ 예정) 어픽스 시스템 실구현 착수 전, <strong class="font-semibold text-text-0">어픽스 30개 실수치 마스터 시트</strong>와 <strong class="font-semibold text-text-0">프레스티지-어픽스 스택 폭주 방지 규약</strong>을 확정한다. Sprint 01 W1 에서 뼈대(6등급 × 슬롯 수)만 잡아뒀고, Sprint 02 W1/W2 에서 프레스티지 30항목 곱연산 전제가 APPROVED 된 상태 — 이제 어픽스가 프레스티지와 결합 시 <strong class="font-semibold text-text-0">5배 이상 폭주하지 않는지</strong> 시뮬까지 끝내두는 게 본 문서의 핵심 산출.</p>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">1.2 스코프 경계</h3>

<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1">어픽스 30개 실수치 (<code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">affix_pool.tsv</code>)</li><li class="mb-1">등급 6단계 × 슬롯/재롤 규칙 (<code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">affix_slot_rules.tsv</code>)</li><li class="mb-1">10빌드 × 프레스티지·어픽스 스택 시뮬 (<code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">affix_stack_matrix.tsv</code>)</li><li class="mb-1">본 설명 문서 (<code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">affix_pool_README.md</code>)</li></ul>

<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">1.3 1인 파트타임 현실</h3>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1">어픽스 총 30개로 한정. 원본 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OptionItemRandom</code> 211행 대비 -86%. 이유: 2016년 원본은 4직업 × 장비슬롯별 분기 × 세부 보정이 누적된 결과. 2026년 싱글 방치형은 단일 클래스(Berserker 기준)·단일 전투 루프이므로 압축해도 부족 없음.</li><li class="mb-1">카테고리 4종 (Offensive / Defensive / Utility / Economy 통합): Offensive 13 + Defensive 9 + Utility 8 = 30개.</li><li class="mb-1">등급별 tier 컬럼 6개로 동일 어픽스의 Common~Mythic 롤 범위를 한 행에 전개 → Importer 는 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">tier_N</code> 컬럼 런타임 선택 가능.</li></ul>

<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">2.1 확장 근거</h3>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1">Sprint 01 W1 스켈레톤이 Magic=2 / Rare=4 / Epic=6 / Legendary=6 / Mythic=7 슬롯으로 확정 → 그대로 유지.</li><li class="mb-1"><strong class="font-semibold text-text-0">재롤 비용 2축 (PP + Gold)</strong>: Gold 는 경제 루프 소비, PP 는 프레스티지 축 소비. Mythic 재롤은 PP 50 = 프레스티지 소프트캡(Lv5) 10단계 분량 → &quot;재롤 = 성장 기회비용&quot; 체감 유도.</li><li class="mb-1"><strong class="font-semibold text-text-0">롤 범위 %</strong>: Magic=60-100 (하한) / Mythic=100-140 (상한) — 동일 어픽스 tier_6 수치에 0.6~1.4 곱연산. 즉 Mythic &quot;잘 뽑은&quot; 어픽스 = Epic &quot;못 뽑은&quot; 어픽스의 1.75배.</li></ul>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">2.2 prefix vs suffix 구분 (원본 계승)</h3>
<p class="mb-3 text-text-0">원본 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OptionItemRandom</code> 는 Prefix/Suffix 구분을 명시적으로 하지 않고 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OptionDivision + OptionRank</code> 조합으로 분류됐다. 본 시트는 디아블로 식으로 단순화:</p>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">Prefix</strong> (접두): 기본 스탯 증가 — flatAttack, flatHp, attackPct, hpPct, defensePct, bossDmg, packDmg, guardianAtk 등 13개</li><li class="mb-1"><strong class="font-semibold text-text-0">Suffix</strong> (접미): 파생·특수 효과 — critRate, critDmg, attackSpeed, cooldown, dodge, dropRate, goldGain, lifeSteal 등 17개</li></ul>
<p class="mb-3 text-text-0">Importer 는 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">affix_type</code> 컬럼(Prefix/Suffix)을 읽어 슬롯 배치 시 prefix 슬롯에는 Prefix 어픽스만 롤하도록 필터. Mythic 의 4:3 비대칭은 Prefix 1개 추가.</p>

<h2 class="mb-3 mt-6 text-[18px] font-semibold text-gold-light">3. 프레스티지 stat_key 중복 / 스택 규약</h2>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">3.1 문제 제기</h3>
<p class="mb-3 text-text-0"><code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">prestige_items.tsv</code> 30항목 중 <strong class="font-semibold text-text-0">19개가 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">affix_pool.tsv</code> 와 stat_key 동일</strong> (예: <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">AttackPct</code>, <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">CritRatePct</code>, <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">MaxHpPct</code>, <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">DropRatePct</code>, <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">IdleYieldPct</code>, <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">GuardianAtkPct</code> 등). 두 축 모두 곱연산 전제라면 폭주:</p>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>naive_mult = (1 + prestige) × (1 + affix)
예: AttackPct 프레스티지 Lv50 +11% × 어픽스 Epic 9슬롯 평균 합 +24%
   = 1.11 × 1.24 = 1.376 → 문제없음

그러나 IdleYieldPct:
   프레스티지 Lv50 +13% × 어픽스 tier_6 평균 +19% = 1.13 × 1.19 = 1.345
   + 여기에 MagicFind 곱연산 + DropRate 곱연산 + GoldGain 곱연산
   = 1.3 × 1.3 × 1.4 × 1.4 ≈ 3.31x 방치 보상
   → 방치 드립이 초기 의도(§3.2) 대비 3배 폭주</code></pre>

<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">3.3 수식 (Calculator 인터페이스용)</h3>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>finalMult(stat) =
  if stack_policy == exclusive_onlyOne:
      1 + max(prestige[stat], Σ affix[stat])
  elif stack_policy == additive_hardcap:
      1 + min(hardcap[stat], prestige[stat] + Σ affix[stat])
  else:  # additive_crossAxis or additive
      1 + prestige[stat] + Σ affix[stat]

finalDps = baseDps × Π finalMult(stat) for each stat axis</code></pre>
<p class="mb-3 text-text-0"><strong class="font-semibold text-text-0">핵심</strong>: 같은 stat 내부는 덧셈, 서로 다른 stat 축만 곱연산. <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">prestige_system_spec.md</code> §5.2의 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">1.18 × 1.11 × 1.36 × 1.16 ≈ 2.05×</code> 와 정합 (각 축은 프레스티지+어픽스 덧셈 합산 결과).</p>

<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">Q5. B08~B09 Mythic 폭주 (overflow 2.5~3.0x) — 허용 vs 제약?</h3>
<p class="mb-3 text-text-0">본 시트 §4.3에서 &quot;의도된 과성장&quot; 으로 판정했으나, 시즌 랭킹·PvP 없는 싱글 방치형에서 과성장이 오히려 &quot;재미 소모 가속&quot; 일 수 있음. 대안:</p>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1">(a) 허용 (의도된 장기 목표 달성감)</li><li class="mb-1">(b) Mythic 어픽스 자체에 &quot;중복 슬롯 금지&quot; (예: AttackPct 어픽스는 장비 1종에만) 추가 규칙</li><li class="mb-1">(c) Mythic 아이템 동시 장착 상한 (예: 최대 2개)</li></ul>
<blockquote class="my-3 rounded border-l-2 border-gold bg-bg-2 px-4 py-2 text-text-1">권장: (a). 단 Sprint 05+ 시즌 도입 시 실측 후 (b)(c) 재검토.</blockquote>
<hr class="my-6 border-border" />
<h2 class="mb-3 mt-6 text-[18px] font-semibold text-gold-light">6. Sprint 04 code-lead 인계용 체크리스트</h2>
<p class="mb-3 text-text-0">Importer 구현 시 다음 6개 필수:</p>
<ol class="mb-3 ml-5 list-decimal text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">TSV 파서 tier_1~tier_6 범위 문자열 파싱</strong> — <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">&quot;10-15&quot;</code> 또는 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">&quot;0.3-0.6&quot;</code> 형식. <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">Range&lt;float&gt;</code> 구조체로 변환. Min/Max 역전(<code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">15-10</code>) 감지 시 Editor Error.</li><li class="mb-1"><strong class="font-semibold text-text-0">stack_policy enum 4종 처리</strong> — <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">additive_crossAxis</code> / <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">additive_hardcap</code> / <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">exclusive_onlyOne</code> / <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">additive</code>. Calculator 확장 메서드 분기 (§3.3 수식). Unknown policy 는 Fail-loud.</li><li class="mb-1"><strong class="font-semibold text-text-0">prestige_overlap 컬럼 매핑</strong> — <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">prestige:AttackPowerPct</code> 형식. Importer 가 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">prestige_items.tsv</code> 의 stat_key 와 일치하는지 교차검증. 불일치 시 Editor Error (prestige/affix 싱크 깨짐 방지).</li><li class="mb-1"><strong class="font-semibold text-text-0">required_item_class 필터</strong> — <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">weapon,accessory</code> / <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">armor,accessory</code> / <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">armor</code> / <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">weapon</code> 콤마 구분. 슬롯 롤링 시 해당 클래스 아이템에만 등장. 파서 trim 필수.</li><li class="mb-1"><strong class="font-semibold text-text-0">slot_weight 가중치 추첨</strong> — 30개 어픽스의 weight 합을 구한 뒤 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">Random.Range(0, totalWeight)</code> 로 누적 선택. 원본 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OptionItemRandom.OptionRate</code> 10000분율 방식 재활용 (Sprint 01 W1 README §2.2 참조).</li><li class="mb-1"><strong class="font-semibold text-text-0">affix_stack_matrix 자기검증 테스트</strong> — <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">Tests.Editor</code> 에 10빌드 수치를 하드코딩하여 Calculator 결과와 ±5% 이내 일치 확인. 벗어나면 Red. Sprint 04 종료 Definition of Done 조건.</li></ol>
