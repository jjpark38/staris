3. 소프트캡 공식 (Calculator 수식화 가능)

3.1 수식

CalculateLevel(int investedPp, byte softCap=5):
    누적 비용 테이블(prestige_pp_cost.tsv)로 역조회 — cumulative_pp 가 investedPp 이하인 최대 level 반환
    Lv 상한 = 100 (pp_cost.tsv 최종 행)

CalculateBonus(row, level):
    if row.effect_type == PercentStat or Multiplier:
        if level <= softCap:
            bonus = row.per_level_value * level                           // 선형
        else:
            preCap  = row.per_level_value * softCap                       // Lv5까지 쌓인 기본
            postLv  = level - softCap
            bonus   = preCap + row.per_level_value * row.post_softcap_diminish * log2(1 + postLv)
        return row.base_value + bonus
    elif row.effect_type == FlatStat:
        if row.curve_id == FlatCapped:
            return row.base_value + row.per_level_value * min(level, softCap)  // Lv5 이후 증가 없음
        elif row.curve_id == FlatSteps:
            return row.base_value + row.per_level_value * min(level, softCap)  // IdleCapHours 동일

6. Sprint 02 W2 code-lead 임포터 자기검증 체크포인트 (5개)

code-lead 의 PrestigeItemImporter 가 TSV 로드 직후 반드시 검증해야 할 항목:

  1. [CP-T1] 행 수 강제 = 30

    • rows.Count != 30 → InvalidOperationException("PrestigeItemImporter: expected 30 rows, got {n}") + Importer 중단 + DisplayDialog.
    • Sprint 02 범위는 30항목 고정. 29/31 시 튜닝 실수 감지.

  2. [CP-T2] tab 리터럴 화이트리스트

    • 허용값: Offense / Defense / Utility (정확한 PascalCase).
    • Unknown / 소문자 / 공백 포함 시 ArgumentException.
    • 탭별 카운트 검증: Offense=10 / Defense=10 / Utility=10. 불일치 시 중단.

  3. [CP-T3] softcap_level 일률 5

    • 30행 모두 softcap_level == 5 검증. 다른 값이면 경고 로그 + 계속 진행 (Sprint 03+ 항목별 소프트캡 재튜닝 대비 — hard fail 아님).

  4. [CP-T4] item_id 연속성 + 탭 범위 정합

    • item_id = 0..29 연속 정수, 중복 없음.
    • Offense: 09 / Defense: 1019 / Utility: 20~29 범위 정합 (소프트 검증, 불일치 시 경고만).

  5. [CP-T5] per_level_value 수치 범위

    • PercentStat / Multiplier: 0.005 <= per_level_value <= 0.05 (0.5%~5% 범위). 벗어나면 경고 (오탈자 감지).
    • FlatStat: per_level_value >= 1.0 (정수 단위). 0 이면 ArgumentException.
    • post_softcap_diminish: 0.15 <= x <= 0.50 범위. 벗어나면 경고.

추가: prestige_pp_cost.tsv 검증 (선택):

  • level 1~100 연속. 단조 증가 (cost_pp[n] >= cost_pp[n-1]).
  • cumulative_pp 누적 일관성 (cumulative_pp[n] == cumulative_pp[n-1] + cost_pp[n]). 중간 레벨(51,55,60..95) 생략행은 비선형 샘플링이므로 연속성 검증은 건너뛰고 행별 cumulative_pp 단조 증가만 확인.

7. Sprint 03+ 실측 튜닝 대기 리스트

7.1 최우선 튜닝 대상 (Sprint 03 플레이테스트 직후)

  1. item_id=0 공격력 per_level 2.0%: 다른 곱연산 축(치피·보스)과 곱해지면 체감 폭이 너무 클 수 있음. 1.5%로 하향 가능성.
  2. item_id=24 방치 수익 증폭 per_level 3.0%: 복리 루프 (방치로 PP 적립 → PP 찍어 방치 수익 증폭 → 더 많은 방치 PP). 폭주 감지 시 1.5%로 하향 + 하드캡 추가.
  3. item_id=26 PP 획득량 per_level 1.5%: 메타 가속 축. 모든 원천에 곱해지면 소프트캡 이후에도 복리 효과 우려. diminishing 0.25 → 0.15 로 강화 가능.

7.2 후순위 튜닝 대상 (Sprint 04+ 장비 도입 후)

  1. 장비 기여 15배 가정 재검증: Sprint 03 Mythic 장비 스펙 확정 후 200층 역산 재계산. 장비 기여가 10배로 축소되면 프레스티지 필요 기여 ↑ → per_level 계수 일괄 상향.
  2. item_id=9 장비 옵션 증폭 0.8%: 장비 어픽스 풀 크기·기대값이 확정돼야 의미 결정. 현 0.8%는 잠정.
  3. item_id=25 방치 캡 시간 최대 +10h: 34h 캡이 유저 패턴에 맞는지. 광고 48h 확장과의 중복 허용 여부 (현재 별도 누적 가정).

7.3 Sprint 05 시즌 도입 전 재논의 (Q3 관련)

  1. seasonalPP 50% 전환 비율: 현 스펙 Q3 결정. 실제 시즌 반복 동기가 약하면 70%로 상향 검토.

  • (b) 개별 어픽스마다 내부 가산
  • 권장: (a). Sprint 04 어픽스 풀 확정 전 잠정.
