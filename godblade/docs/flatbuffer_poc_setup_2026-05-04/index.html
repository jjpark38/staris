1. PoC 목적 (3건)

  1. flatc 컴파일러 검증 — Linux/Windows binary 다운로드 + .fbs 컴파일 성공 + C# / TypeScript binding 생성
  2. GitHub Actions CI 통합 가능성 — flatc ubuntu-latest 실행 + Unity Editor batch mode (game-ci/unity-builder@v4) 호출 + 한가영 검증 라인 인터페이스
  3. 실패 시 차선 (Protobuf) — FlatBuffer 검증 실패 시 fallback 비용·리스크 1쪽

2. flatc 검증 절차 (정현우 로컬 + CI)

2.1 로컬 검증 (Windows, 정현우 박세린 합의 - 본인 메인 OS)

# 1. flatc 24.3.25 Windows binary 다운로드
# https://github.com/google/flatbuffers/releases/download/v24.3.25/Windows.flatc.binary.zip
# 압축 해제 -> C:\tools\flatc\flatc.exe
# PATH 등록 -> 새 터미널에서 검증
flatc --version
# 기대 출력: flatc version 24.3.25

# 2. schema 컴파일 검증
cd D:\SVN\Backup\GodBlade
flatc --csharp -o generated\csharp designs\flatbuffer_schema_draft_v0_1.fbs
flatc --ts -o generated\typescript designs\flatbuffer_schema_draft_v0_1.fbs

# 3. 생성 파일 확인
# generated\csharp\GodBlade\Schema\*.cs (table 1개당 1 파일)
# generated\typescript\god-blade\schema\*.ts

기대 결과:

  • C# 파일 8~10개 생성 (AffixPool / PrestigeItems / TranscendentMilestone / GodBladeData + 각 enum + helper)
  • TS 파일 동일 구조
  • 0 오류

위험: Windows binary 가 Linux 와 다른 별도 검증 필요. 실패 시 Docker google/flatbuffers 이미지 fallback.

2.2 CI 검증 (GitHub Actions, 차도윤 + 임재훈 인계 의제)

designs/flatbuffer_github_actions_draft.yml 참조. 4 job 구성:

  1. flatc-compile — .fbs -> C# / TS binding 생성
  2. unity-so-export — game-ci/unity-builder@v4 Unity 6000.0.23f1 batch mode + FlatBufferImporter.RunCI() 호출
  3. phaser-json-export — webgame/ 측 Vite 빌드 + binary export (차도윤 영역)
  4. balance-regression — Unity binary ↔ Phaser binary diff + 200F 4.255 baseline 검증 (한가영 영역, Sp-W01 W2 활성화)

위험 3건 (yaml 하단 주석 참조):

  • game-ci/unity-builder Unity 6000.0.23f1 호환성 — D+14 합의 시 검증 필요
  • flatc Windows binary 별도 검증
  • 한가영 도구 미작성 → Sp-W01 W2 (5/25) 1:1 PoC 4h 후 활성화

3. Unity Editor batch mode 호출 절차 (정현우 영역)

3.2 진입점 시그니처

// Unity6/Assets/Editor/FlatBuffer/FlatBufferImporter.cs (Sp-W01 W1 작성, 본 PoC 는 시그니처만)
namespace GodBlade.EditorTools
{
    public static class FlatBufferImporter
    {
        // GitHub Actions yaml job 2 진입점
        // -executeMethod GodBlade.EditorTools.FlatBufferImporter.RunCI
        public static void RunCI()
        {
            // 1. designs/flatbuffer_schema_draft_v0_1.fbs 로드
            // 2. Datasheets/*.tsv -> FlatBufferBuilder 변환 (TsvReader 통합 - Sp02 이월)
            // 3. godblade_data.bin export -> Unity6/Assets/_Project/Generated/
            // 4. SO 3개 (AffixPool / PrestigeItems / TranscendentMilestone) 생성 + Addressables 등록
            // 5. exit code 0 (정상) / 1 (실패)
        }
    }
}

Sp01 W2 Importer 와 영역 분리:

  • W2 Importer (DropRateTableImporter / MilestoneRewardImporter / AffixPoolImporter) = TSV 직접 파싱 → SO
  • 본 FlatBufferImporter = TSV → FlatBuffer binary → SO (중간 레이어 추가)
  • Sp-W01 W1 (5/18~5/24) = FlatBufferImporter 신설 + Sp01 W2 Importer 3종 호출 wrapper 화 (TsvReader Sp02 공통화 시 흡수)

4. 차선 검토 — Protobuf fallback 비용·리스크 1쪽

4.1 FlatBuffer 검증 실패 trigger 조건

  • flatc Windows binary 실행 실패 (Docker fallback 도 실패)
  • game-ci/unity-builder Unity 6 호환성 0 (self-hosted runner 도 실패)
  • C# binding zero-copy 검증 시 메모리 leak 발견

4.2 Protobuf 차선 비교

항목FlatBuffer (현 채택)Protobuf (차선)

4.3 Protobuf 전환 비용

  • 정현우 50h 재작업 필요 (schema.fbs → schema.proto / FlatBufferImporter → ProtobufImporter)
  • 차도윤 30h 재작업 필요 (Phaser export 재구현)
  • 한가영 도구 재작성 (binary diff → JSON diff)
  • 총 ~80h 재작업 + 일정 1~2주 추가 지연

4.4 결정 트리

flatc 로컬 검증 PASS?
  ├─ YES → CI 검증 PASS?
  │         ├─ YES → FlatBuffer 채택 잠금 (D+14 v1.0 APPROVED)
  │         └─ NO  → self-hosted runner 검증
  │                    ├─ PASS → FlatBuffer 채택 (CI 단순화)
  │                    └─ FAIL → Protobuf 차선 검토 PD 보고
  └─ NO  → Docker google/flatbuffers 이미지 fallback
            ├─ PASS → FlatBuffer 채택 (Docker 의존)
            └─ FAIL → Protobuf 차선 검토 PD 보고
