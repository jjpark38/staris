## §13. 특수 리스크 — struct+List hot path vs SO 카탈로그 패턴 충돌

### §13.1 문제 정의

Sp01 W2 DQ1 결정: **`DropRateTableSO` / `MilestoneRewardCatalogSO` / `AffixPoolSO` = SO 옵션 A** (개별 SO, read-only 카탈로그).

Sp02 W2 Q1 결정: **`PlayerPrestigeState` = 옵션 B** (`PrestigeSlot` blittable struct + `List<PrestigeSlot>`, read-write hot path).

**Sp02 W1**: `PrestigeItemCatalogSO` 는 **Sp01 W2 옵션 A 재활용** (read-only 정적 카탈로그). `PrestigeSlot` / `PlayerPrestigeState` 는 **W2 에서 도입**.

두 패턴이 **프로젝트 구조상 의도적으로 공존**하나, Sp02 W1 종반 → W2 킥오프 사이 1주 간격으로 **동일 개발자(code-lead)가 두 패턴을 연속 작성**. 혼동 유발 여지.

### §13.2 혼동 시나리오 3건

1. **시나리오 1**: `PrestigeItemCatalogSO.rows` (List<PrestigeItemRow>) 와 `PlayerPrestigeState._slots` (List<PrestigeSlot>) 가 **모두 List 기반** → 개발자가 W2 작성 중 "이거 SO로 하면 되잖아?" 독단 결정 가능성. 설계 §1.2 3옵션 비교표 재확인 필요.
2. **시나리오 2**: `PrestigeItemRow` (Data asmdef) vs `PrestigeSlot` (Runtime asmdef) — 어셈블리 다르나 **파일명/네임스페이스 유사** (`Prestige` 서브 네임스페이스 공유). `using` 실수로 잘못된 타입 참조 시 CS0104 (ambiguous reference) 위험.
3. **시나리오 3**: `OnEnable` lazy build (Sp02 W1 SO 패턴) vs `OnApplicationPause` 즉시 flush (Sp02 W2 State 패턴) — 생명주기 관리 2축 공존. 혼동 시 "왜 SO에서도 flush 필요하지?" 같은 오해 여지.

### §13.3 완화책

- **W1 PR 본문 필수 1줄**: "본 PR은 Sprint 01 W2 DQ1 옵션 A (SO 카탈로그) 재활용. W2 도입 예정인 `PlayerPrestigeState` 옵션 B (struct+List) 와 **의도적 분기**. 두 패턴은 다른 어셈블리·다른 성격(read-only vs read-write)."
- **코드 주석 1줄**: `PrestigeItemCatalogSO.cs` 파일 최상단 다음 주석 명시:
  ```csharp
  // read-only catalog. Runtime mutable state → see GodBlade.Runtime.Prestige.PlayerPrestigeState (Sp02 W2)
  ```
- **CP-M06 강화**: 네임스페이스 컨벤션 `GodBlade.Data.Prestige` (카탈로그) / `GodBlade.Runtime.Prestige` (상태) 물리적 구분. Sp02 W2 설계 §8 CP-P1 재확인 (`PpChannel` 은 Runtime에만).
- **PR 리뷰 포인트 1건 추가**: W2 작성 시점에 "`PrestigeSlot` 은 SO에 저장 금지, 반드시 `PlayerPrestigeState` 내부 List" 체크.

### §13.4 충돌 리스크 판정

| 축 | Sp02 W1 (SO 카탈로그) | Sp02 W2 (struct+List) | 충돌 리스크 |
|---|-----------------------|----------------------|------------|
| 어셈블리 | GodBlade.Data | GodBlade.Runtime | **Zero** (물리적 분리) |
| 네임스페이스 | GodBlade.Data.Prestige | GodBlade.Runtime.Prestige | **Low** (서브 네임스페이스 혼동 여지) |
| 데이터 구조 | List<PrestigeItemRow> | List<PrestigeSlot> | **Medium** (List 패턴 동일) |
| 생명주기 | OnEnable lazy build | OnApplicationPause/Quit flush | **Low-Medium** (생명주기 축 다름) |
| 직렬화 | Unity SO auto | JsonUtility explicit | **Low** (직렬화 엔진 다름) |
| 개발자 혼동 | — | 1주 연속 작성 | **Medium** (W1→W2 전환 시점) |

**종합**: **Medium**. 설계상 분리는 명확하나 **휴먼 에러** 축에서 주의 필요. 완화책 4건 적용 시 Low로 축소 가능.
