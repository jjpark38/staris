## 1. 배경

2026-04-21 Sp00 D+2 버퍼 기간 10건 APPROVED 설계 문서 헤더 재점검 결과 포맷 drift 2건 확인:

- **버전 표기**: `v1.0 APPROVED` (7건) vs `APPROVED v1.0` (3건)
- **승인자 명기**: 최초 문서 1건만 이메일 병기, 9건은 간소화

기능 영향 0이나 향후 PR 리뷰·grep 검증 시 일관성 확보 및 신규 작성자(game-designer/code-lead/메인 세션) 혼란 방지 목적으로 본 규약 제정.

## 2. 표준 헤더 블록 (권장)

```markdown
# <문서 제목>

> 작성: YYYY-MM-DD (<작성자 역할>) · <서브 맥락 1줄>
> 버전: **v1.0 APPROVED** (PD 승인 YYYY-MM-DD)
> 상위 참조: `designs/<상위 문서>.md` v1.0 APPROVED
> 범위: <1줄>
>
> ---
```

**필수 5요소**:

1. `# <문서 제목>` — H1 헤딩 1개
2. `작성: YYYY-MM-DD (<역할>)` — ISO-8601 날짜 + 괄호 역할
3. `버전: **v1.0 APPROVED** (PD 승인 YYYY-MM-DD)` — 굵은체 + 승인일
4. `상위 참조: <경로> v1.0 APPROVED` — 상위 문서가 있으면 명시
5. `범위: <1줄>` — 문서 스코프 1줄 요약

**선택 요소** (문서 성격에 따라 추가):

- `승인자: PD <이메일>` — 최초 승인(v1.0) 시 1회 한정 이메일 명기. v1.1 이상 개정 시 생략
- `CP 추적: CP1(§3) · CP2(§4) ...` — 체크포인트 있는 기술 설계 문서
- `> **PD 결정 (YYYY-MM-DD)**:` 블록 — 복수 결정(Q1~Qn) 문서

---

## 3. 버전 표기 통일 원칙

**채택**: `v1.0 APPROVED` (v 접두사 앞, APPROVED 뒤)

- 이유: 10건 중 7건 다수 표기 계승. `v`로 시작하면 정렬·grep 용이.
- 비추천: `APPROVED v1.0` (순서 반대). 2026-04-21 이전 3건(`transcendent_reward_draft.md` / `sprint-01-w2-importer-design.md` / `sprint-02-w2-prestige-tech-sketch.md`) 은 **과거 기록으로 유지** — 소급 수정 금지 (히스토리 보존).

**개정 시 버전 번호 규칙**:

- 초안 (PD 미승인): `v0.1 DRAFT` / `v0.2 DRAFT` ...
- 최초 승인: `v1.0 APPROVED`
- 수치/스펙 수정 (breaking 아님): `v1.1 APPROVED` / `v1.2 APPROVED` ...
- 구조 변경 (breaking): `v2.0 APPROVED` / `v3.0 APPROVED` ...
- Sp06+ 이월 후 재개: `v2.0 APPROVED (Sp06 재승인)`

---

## 4. 승인자 명기 규칙

- **최초 v1.0 APPROVED**: 이메일 병기 **선택** — 중요 결정 문서(5대 결정 이상)는 이메일 명시 권장
- **v1.1 이상 개정**: 이메일 생략, `(PD 승인 YYYY-MM-DD)` 만
- **승인 없음 (DRAFT)**: `상태: DRAFT (YYYY-MM-DD, PD 승인 대기)` 명시

이메일 명시 포맷: `승인: PD mobydickaquainc@gmail.com (YYYY-MM-DD)` 별도 라인
