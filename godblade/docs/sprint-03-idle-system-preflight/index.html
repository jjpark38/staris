1.4 B04 100층 10h = PP 50 검증 양식 (CP-I4 idle-research §9.2 답습)

수식: prestige_system_spec.md §3.2(C) ppGained = floor((elapsedSec / 3600) × maxFloor × 0.05 × prestigeBonus.IdleRateMul)

입력 (Smoke Test #09 시뮬값, A4 사전 메모 = sprint-03-dry-run §0.3 A4):
  elapsedSec = 36000  (10h)
  maxFloor = 100
  prestigeBonus.IdleRateMul = 1.0f  (무투자)
  idleCapHours = 24  (무투자, TSV #25 Lv0 기본)

cap 적용:
  cappedSec = min(36000, 24 * 3600) = min(36000, 86400) = 36000  ✅ (cap 미적용)

PP 수식:
  ppGained = floor((36000 / 3600) × 100 × 0.05 × 1.0)
           = floor(10 × 100 × 0.05)
           = floor(50.0)
           = 50  ✅

기대값: Debug.Log("[Idle] +50 PP, elapsed=36000s") 출력

합/불합 판정:

  • PASS: ppGained == 50 정확 일치
  • FAIL: 49 또는 51 → 수식 검증 (floor vs round 혼동? 곱셈 순서?). Calculator 내부 수식 grep 1회

IdleTicker.FlushCatchUp() 내부 순서 락 (CP-I7):

2. IdleRewardCalculator.Calculate(...) → IdleRewardBundle
3. 배치 발화 (순서 절대 변경 금지):
   a. bundle.MilestonesReached.ForEach(floor => MilestoneGranter.Award(floor))
      └─ floor==100 시 PlayerPrestigeState.Unlock() 연쇄 (Sp02 W2 계약)
      └─ floor==200 시 PrestigePpAccumulator.GrantMilestone(200) 연쇄
   b. bundle.KillsTotal / DropsCompact → Debug.Log (Q5 = A 로그만, Sp03 인벤토리 미도입)
   c. PrestigePpAccumulator.GrantIdleDrip(elapsed, maxFloor)
      └─ 내부 = PlayerPrestigeState.AddPermanentPp(ppGained) 호출
   d. OnIdleReward?.Invoke(bundle)  // UI 알림 (보고용, 수령 절차 X)
4. IdleSaveService.Save()  // lastTickUtc 갱신

불변식 (CP-I6): OnIdleReward 발화 시점엔 Milestones · Drops · PP 모두 이미 적용. UI 는 후처리 표시만. 이중 적립 금지.
