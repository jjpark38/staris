<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">§14.2 iOS Suspend 시나리오 분석</h3>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>T+0   : 유저 Home 버튼 누름
T+0.5s: OnApplicationPause(true) 발화 → _lastTickUtc = DateTime.UtcNow 저장 (성공 예상)
T+30s : iOS 앱 Suspend (프로세스 동결)
T+10min: 유저 앱 재진입
T+10min+ε: OnApplicationPause(false) 발화 (iOS Resume)
         → FlushCatchUp() 호출, elapsed = 10min 계산 정상</code></pre>
<p class="mb-3 text-text-0"><strong class="font-semibold text-text-0">문제 시나리오</strong>: T+30s 이전에 iOS 가 앱을 <strong class="font-semibold text-text-0">즉시 Kill</strong> (메모리 압박) → OnApplicationPause(true) 미발화 → _lastTickUtc 미저장 → 재시작 시 Save 파일의 이전 값 사용, 30초 ~ 10분 격차 누락 가능성.</p>
<p class="mb-3 text-text-0"><strong class="font-semibold text-text-0">완화</strong>:</p>
<ol class="mb-3 ml-5 list-decimal text-text-0"><li class="mb-1"><code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">Update()</code> 내 1분 주기 Safe Flush (CP-M22) — 1분 이내 격차만 허용</li><li class="mb-1"><code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OnApplicationQuit</code> 이중 저장 (설계 §1.4) — iOS는 호출 보장 약함, Android는 상대 강함</li></ol>

<h2 class="mb-3 mt-6 text-[18px] font-semibold text-gold-light">§15. IdleTicker MonoBehaviour Singleton 리스크 상세</h2>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">§15.1 singleton 패턴 취약점 3건</h3>
<div class="my-4 overflow-x-auto"><table class="w-full border-collapse text-[13px]"><thead><tr><th class="border border-border bg-bg-2 px-3 py-2 text-left font-semibold text-gold-light">취약점</th><th class="border border-border bg-bg-2 px-3 py-2 text-left font-semibold text-gold-light">발생 조건</th><th class="border border-border bg-bg-2 px-3 py-2 text-left font-semibold text-gold-light">대응</th></tr></thead><tbody><tr><td class="border border-border px-3 py-2 text-left text-text-0"><strong class="font-semibold text-text-0">중복 생성</strong></td><td class="border border-border px-3 py-2 text-left text-text-0">씬 전환 시 DontDestroyOnLoad 누적 — 다른 씬에 IdleTicker 프리팹 배치 시 2개 이상</td><td class="border border-border px-3 py-2 text-left text-text-0">Awake 가드: <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">if (_instance != null &amp;&amp; <h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">§15.2 DontDestroyOnLoad 누적</h3>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1">IdleTicker GameObject를 어느 씬에 배치하는가? — Sp03 범위에선 <strong class="font-semibold text-text-0">부트스트랩 씬 (현재 없음)</strong> 전제. Sp04+ 씬 구조 확정 후 프리팹 배치 재검토</li><li class="mb-1">임시 방안: <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">IdleTicker</code> 를 static 메서드로 초기화 — <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]</code> → GameObject 자동 생성</li><li class="mb-1"><strong class="font-semibold text-text-0">권장</strong>: Sp03는 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">RuntimeInitializeOnLoadMethod</code> 로 1회 자동 생성 + DontDestroyOnLoad. 프리팹 의존성 Zero</li></ul>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">§15.3 씬 전환 시 연속성</h3>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1">Sp03 범위에선 씬 전환 없음 (Smoke Test 단일 씬). Sp04+ 로비 ↔ 스테이지 씬 전환 도입 시 재검증 필요</li><li class="mb-1">완화: <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">_instance</code> static 필드 + DontDestroyOnLoad 로 씬 독립. 씬 전환 시 OnApplicationPause 미발화 확인</li></ul>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">§15.4 OnDestroy 순서 리스크</h3>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1">Play Mode 종료 시 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OnDestroy</code> 호출 → <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">IdleSaveService.Save</code> 시도 — 이미 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">_instance=null</code> 이면 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">_prestige</code> 필드 접근 실패 가능</li><li class="mb-1">완화: OnDestroy에서 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">try/catch</code> + <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">_instance != null</code> 가드 먼저</li></ul>
