> 이 파일은 GodBlade 프로젝트에서 Claude(또는 다른 AI 코딩 에이전트)가 첫 세션을 열 때 프로젝트 맥락을 빠르게 파악하도록 작성되었습니다.

## 프로젝트 개요 (한 줄 요약)

**GodBlade** (구 이름: Eternal Guardians / EOD, 중원게임즈 2015~2016) 는 10년 전에 만들어진 Unity 멀티플레이어 RPG이며, **최신 Unity 6 + 싱글 플레이어 중심 + 글로벌 출시**로 리부트하는 장기 프로젝트입니다.

## 현재 상태 (2026-04-20)

- **원본 Unity 버전**: `2019.4.11f1 LTS` (2020년 8월 릴리스)
- **원본 서버 스택**: .NET Framework 3.5/4.5 + IIS + MySQL Cluster + Redis (Windows Server)
- **원본 서버 수**: 29개 프로젝트 (~50,000 LOC)
- **Phase**: Phase 1 (현황 파악) — 진행 중

## 목표

| 항목 | 현재 | 목표 |
|------|------|------|
| Unity | 2019.4 LTS | **Unity 6 LTS** |
| 게임 모드 | 멀티 RPG (파티/길드/PvP/점령전) | **싱글 플레이어** |
| 서버 | 29개 Windows .NET 서버 | **서버리스 (Firebase만)** |
| 플랫폼 | 모바일 | **Steam + iOS/Android** |
| 언어 | 한국어 | **5개 언어 (한/영/중간/일/스)** |
| 수익 | 없음 (방치) | Steam 유료 + 모바일 유료/광고 |

## 개발 체제

- **1인 파트타임 개발자** (본업 병행)
- **예상 기간**: 24~30개월
- **예상 출시**: 2028년 1월

## 진행 원칙

1. **원본은 절대 수정 금지** — `D:\SVN\Backup\GodBlade\` 는 2021년 스냅샷. 새 Unity 6 프로젝트는 별도 폴더에 생성.
2. **1인 파트타임 현실 반영** — 한 세션은 "2~4시간 집중 단위"로 끝낼 수 있는 크기로 잘라서 진행.
3. **검증 우선** — 밸런스 데이터는 DB 덤프 원본이 진실. 추측 금지.
4. **Phase 순서 준수** — 현황 파악 → 설계 → Unity 6 → 싱글 로직 → 백엔드 → 로컬라이즈 → 출시.

## Graphify 사용

이 프로젝트는 코드 규모가 크고(~5만 LOC) 10년 전 작성되어 원저자도 기억이 희미합니다. **Graphify 지식 그래프를 `graphify_output/`에 빌드하면 모든 AI 세션이 코드 구조를 즉시 파악**할 수 있습니다.

설치·실행 방법: **`Graphify_설치_실행_가이드.md`** 참조.

Graphify 결과물이 `graphify_output/` 에 있으면 AI 에이전트는 **반드시 그 폴더부터 먼저 조회**한 뒤 개별 파일을 탐색해야 합니다.

## AI 팀 운영 규약

Phase 2부터 PD(사용자)는 3명의 **AI 서브에이전트 직원**과 함께 일한다. 각 에이전트는 `.claude/agents/*.md`에 정의되어 있고 `Agent(subagent_type: "...")`로 호출한다.

### 팀 구성

| 에이전트 | 역할 | 주 책임 |
|---------|------|---------|
| `game-designer` | 기획PD (RPG 20년차 / 디아블로 감성) | 밸런스 수치, 컨텐츠 루프, 아이템·스킬 스펙 |
| `code-lead` | 프로그래밍 리드 (Unity 6 / DOTS / Addressables 2.x) | Unity 6 코드, 포팅 스프린트, 기술 리스크 |
| `web-lead` | 웹팀장 (Next.js 14 / Supabase / Vercel / Notion API / Gemini Pro) | 통합 웹앱 1차~5차 (대시보드/DevLog/피드백·UGC/강시연 도구/UGC 웹툰), 호스팅·인증·배포 자동화. **2026-05-04 신규 채용** |
| `project-manager` | PM (하네스 공법) | 2주 스프린트, TodoWrite, 의존성·블로킹 추적 |

메인 대화(Claude Code 세션 자체)는 **PD의 비서 겸 오케스트레이터** — PD 지시를 받아 적절한 서브에이전트를 호출하고 결과를 요약 전달한다.

### 호출 컨벤션

- PD가 업무 지시할 때 에이전트 이름을 명시: "기획PD, 무한던전 보상 초안" / "프로그래밍 리드, Sprint 1 계획" / "PM, 이번 주 번다운"
- 독립 작업 여러 개를 동시 발주할 땐 한 메시지에 Agent 툴 2~3개 **병렬 호출**
- 에이전트 결과 보고는 **메인 세션에서 PD에게 1쪽 요약**으로

### 에이전트 협업 프로토콜 (Claude-Code-Game-Studios 선별 채택, 2026-04-21)

1. **Question → Options → Decision → Draft → Approval** 순서 엄수 — 메인 세션/서브에이전트가 PD에 옵션 2~3개 제시 후 PD 선택을 받고 초안 작성, 최종 승인까지 받은 뒤 진행.
2. **Unity6/ 신규 코드·씬·프리팹 생성 전 PD 경로 승인**: 서브에이전트가 `Unity6/Assets/**` 하위 파일을 **신규 생성**할 때는 사전에 경로를 명시하고 PD 승인 1회 필요. 기존 파일 수정은 태스크 맥락 내 자동 OK.
3. **설계 문서 (`designs/*.md`) / 스프린트 문서 (`sprints/*.md`)** 는 본 규칙에서 제외 (빠른 반복 우선).

### 계층 (Tier) 표기

- **Tier 1 Director**: PD (creative + technical + producer 통합, 1인 파트타임)
- **Tier 2 Lead**: `game-designer` / `code-lead` / `project-manager` (3 agent 고정)
- **Tier 3 Specialist**: 미도입. Phase 3 (Sp06+) 시점 `unity-addressables-specialist` / `unity-dots-specialist` / `unity-shader-specialist` / `unity-ui-specialist` 4 후보 재평가 예정 (`project_framework_phase3_reevaluation.md` 메모리 참조).

### 2주 스프린트 사이클

1. **D+0 킥오프**: PM이 `sprints/sprint-NN.md` 킥오프 섹션 작성 (목표 3건, TodoWrite 리스트, 리스크 3건)
2. **작업 기간 (2주)**: PD가 game-designer / code-lead에게 단일 과제 발주
3. **D+14 종료**: 3명 각자 실적 요약 → PM이 `sprint-NN.md`에 종료 섹션 통합 → PD 회고

### 산출물 위치

- 에이전트 정의: `.claude/agents/*.md`
- 스프린트 문서: `sprints/sprint-NN.md` (PM 소유)
- 기획 스펙: `designs/<topic>.md` (game-designer 소유)
- Unity 6 프로젝트 코드: `Unity6/` 하위 (code-lead 소유, 원본 `Program/`과 물리적 분리)
- 원본 `Program/`, `Datasheets/`, `Dump20210311.sql` → **read-only** (SVN 2021 스냅샷)

### 역할 경계 분쟁 해결

- game-designer가 "이 스킬 쿨다운은 이래야 해" → 수치만. 구현 방식은 code-lead 영역
- code-lead가 "이 밸런스 수치 이상함" → PD·game-designer에게 에스컬레이션. 독단 수정 금지
- PM은 **결정권 없음**. 블로킹·선 넘음 사항은 PD에게 보고만
