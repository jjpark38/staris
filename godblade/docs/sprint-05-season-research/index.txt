<h2 class="mb-3 mt-6 text-[18px] font-semibold text-gold-light">2. <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OnSeasonEnd</code> 이벤트 발화 전략 — 3옵션 비교</h2>
<p class="mb-3 text-text-0">Sprint 02 W2 §6.2 신규 훅 3개 중 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OnSeasonEnd</code> 만 <strong class="font-semibold text-text-0">구독자 존재 / 발화자 없음</strong> 상태. Sprint 05에서 발화자를 어디에 둘지 결정한다.</p>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">2.1 옵션 A — 관리자 수동 트리거</h3>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>UI: Debug 메뉴 &quot;[Season] Force End Current Season&quot; 버튼
   → SeasonController.ForceEnd() 호출
   → OnSeasonEnd 발화
   → PlayerPrestigeState.MigrateSeasonalToPermanent(0.5f)</code></pre>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">장점</strong>: 1인 운영 현실 완벽 부합. 버그·과부하 시 즉시 연장·단축 가능. Phase 4 개발 중 테스트 용이.</li><li class="mb-1"><strong class="font-semibold text-text-0">단점</strong>: 유저 입장에서 불확실성. 상용 출시 시 &quot;운영자가 맘대로 종료한다&quot; 불만 리스크.</li><li class="mb-1"><strong class="font-semibold text-text-0">적합</strong>: Phase 4 (Sprint 05 개발) 기본값. Phase 5 이후에도 &quot;긴급 핸들&quot;로 유지.</li><li class="mb-1"><strong class="font-semibold text-text-0">복구</strong>: Migrate 실행 도중 앱 종료 시 §3.4 참조 — 이중 발화 방지 필수.</li></ul>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">2.2 옵션 B — 로컬 타이머 (앱 시작 시 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">DateTime.UtcNow &gt;= seasonEndUtc</code> 확인)</h3>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>SeasonController.Update() (1초 또는 앱 포커스 복귀 시):
  if (now &gt;= seasonEndUtc &amp;&amp; !seasonEnded) {
    OnSeasonEnd 발화
    seasonEnded = true (저장)
  }</code></pre>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">장점</strong>: 서버 없이 작동. 구현 단순 (<code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">IdleTicker</code> 시계 로직 재활용).</li><li class="mb-1"><strong class="font-semibold text-text-0">단점</strong>: <strong class="font-semibold text-text-0">치팅 치명</strong>. 유저가 시스템 시계를 2026-01-01로 되돌리면 시즌이 영원히 종료되지 않거나 반복 종료. Sprint 03 방치 시스템의 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">DateTime.UtcNow</code> 가드는 &quot;음수·30일 초과 경고&quot;만 있고 &quot;조작 자체 차단&quot;은 못함.</li><li class="mb-1"><strong class="font-semibold text-text-0">복구</strong>: 시즌 종료 이벤트 발화 → 앱 종료 → 시계 롤백 시 이중 발화 경로 존재. <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">seasonId</code> 별 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">migrated:bool</code> 플래그로 방어 가능하지만 복잡도 증가.</li><li class="mb-1"><strong class="font-semibold text-text-0">권장 안 함</strong>.</li></ul>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">2.3 옵션 C — Firebase Remote Config <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">currentSeasonId</code> + <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">seasonEndUtc</code></h3>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>앱 시작 / 1h 주기 / 포커스 복귀 시:
  Firebase.RemoteConfig.FetchAndActivate()
  remoteSeasonId = config.currentSeasonId
  if (remoteSeasonId != localSeasonId) {
    // 서버가 시즌 넘어감 선언
    OnSeasonEnd 발화 (localSeasonId 기준 마이그)
    localSeasonId = remoteSeasonId
  }</code></pre>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">장점</strong>: 서버 권위 = 치팅 차단. 글로벌 일괄 전파. <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">seasonEndUtc</code> 표시(클라 카운트다운)와 실제 전환 분리 가능.</li><li class="mb-1"><strong class="font-semibold text-text-0">단점</strong>: Firebase 첫 도입 러닝커브. <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">FetchAndActivate</code> 실패 시 fallback 전략 필요. 오프라인 장기 유저의 &quot;서버보다 1시즌 뒤처진 상태&quot; 처리.</li><li class="mb-1"><strong class="font-semibold text-text-0">적합</strong>: Phase 5+ 상용 기본값.</li></ul>

<ol class="mb-3 ml-5 list-decimal text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">저장 플래그</strong>: <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">lastMigratedSeasonId</code> 기록 (이중 발화 방지)</li><li class="mb-1"><strong class="font-semibold text-text-0">백업 파일 생성</strong>: <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">prestige.v1.json.bak</code> + <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">prestige_season&lt;N&gt;_pre_migrate.json</code></li><li class="mb-1"><strong class="font-semibold text-text-0">UI 이벤트</strong>: <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OnPpChanged</code> 2회(Permanent 증가 / Seasonal→0) + <strong class="font-semibold text-text-0">신규 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OnSeasonEndMigrationCompleted(seasonId, oldSeasonalPp, retainRatio, convertedPp)</code> 이벤트 1건</strong></li><li class="mb-1"><strong class="font-semibold text-text-0">누적 방치 처리</strong>: 시즌 종료 시점에 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">IdleTicker.FlushCatchUp()</code> <strong class="font-semibold text-text-0">강제 1회 실행</strong> → 마지막 방치 PP가 Seasonal 에 반영된 후 Migrate. 순서 뒤집히면 방치 PP가 Permanent 로 직행.</li><li class="mb-1"><strong class="font-semibold text-text-0">마일스톤 스냅샷</strong>: <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">MilestoneGranter</code> 의 현 시즌 maxFloor 을 리더보드 제출 후 리셋 (시즌별 기록 분리)</li></ol>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">3.3 50% 전환 로직 &amp; 라운딩 정책</h3>
<p class="mb-3 text-text-0">Sprint 02 W2 §4.3 의사코드를 확장:</p>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>MigrateSeasonalToPermanent(retainRatio=0.5f):
  // Step 0: 방치 누산 강제 flush (신규)
  IdleTicker.Instance?.FlushCatchUp(forceImmediate: true)

  // Step 1: Seasonal 슬롯 전부 회수
  seasonalInvested = Σ slot.investedPp where channel=Seasonal
  totalPool = SeasonalPp + seasonalInvested   // unspent + invested 모두
  RemoveAll(s =&gt; s.channel == Seasonal)

  // Step 2: retainRatio 적용 — 라운딩 정책 결정 필요 (Open Q6)
  converted = LongMulFloor(totalPool, retainRatio)  // (long * numerator / denominator) 정수 연산
  PermanentPp += converted
  SeasonalPp = 0

  // Step 3: 플래그 저장 + 백업
  lastMigratedSeasonId = currentSeasonId
  PrestigeSaveService.Save(this, accountId)

  // Step 4: 이벤트 발화
  OnPpChanged(Permanent, PermanentPp)
  OnPpChanged(Seasonal, 0)
  OnSeasonEndMigrationCompleted(seasonId, totalPool, retainRatio, converted)</code></pre>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">라운딩 정책 3안</strong> (Open Q6에서 결정):</li><li class="mb-1">(a) <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">Floor</code> — 유저 불리, 대규모 PP 유실 가능 (100 PP → 50 / 101 PP → 50, 1 PP 손실)</li><li class="mb-1">(b) <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">Round</code> — 통계적 중립, 유저·시스템 50:50</li><li class="mb-1">(c) <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">Ceiling</code> — 유저 유리, PP 인플레 약간 가중</li><li class="mb-1">권장: <strong class="font-semibold text-text-0">(b) Round, 소수 첫째자리에서</strong>. 단, 정수 연산 구현 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">(long * 50) / 100</code> → 500 기준 정확한 50% 보장.</li></ul>
