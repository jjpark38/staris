<h2 class="mb-3 mt-6 text-[18px] font-semibold text-gold-light">2. 오프라인 보상 계산 전략 — 3개 옵션 비교</h2>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">2.1 공통 입력</h3>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>inputs:
  elapsedSec       (long)              // DateTime 차 (cap 적용 후)
  maxFloor         (int)               // 현재 최고 도달층
  dropTable        (DropRateTableSO)   // Sprint 01 W2 자산
  milestoneCatalog (MilestoneRewardCatalogSO)
  prestigeBonus    (PrestigeCalculator.BuildSummary — Sprint 02 W2 자산)
  rngSeed          (uint)              // 결정론 재현을 위한 시드</code></pre>
<p class="mb-3 text-text-0">공통 제약:</p>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1"><code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">idleCapHours</code> (프레스티지 #24, 기본 8h Lv당 +1h, 소프트캡 Lv5 → 13h 상한 영역) 초과분은 <strong class="font-semibold text-text-0">드롭</strong>.</li><li class="mb-1">드롭 버킷 Lookup은 Sprint 01 W2 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">Dictionary&lt;(floorBucket, mobKind, grade), float&gt;</code> 재사용 — 신규 Lookup 구조 없음.</li></ul>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">2.2 옵션 A — 이벤트 리플레이 (초당 시뮬)</h3>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>for sec in 0..elapsedSec:
  if sec % killsPerSec == 0:
    KillEvent k = SimulateKill(currentFloor, rng)
    dropTable.RollDrops(k, rng)   // 등급 drop 굴림
    if ShouldAutoAdvanceFloor(...):
      floor++
      CheckMilestone(floor)
  accumulator.Add(k)</code></pre>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">장점</strong>: 온라인 틱 코드 재활용 가능 (동일 로직). 드롭 분포 완전 정확. &quot;방치 로그&quot; UI에 시간대별 이벤트 표현 가능.</li><li class="mb-1"><strong class="font-semibold text-text-0">단점</strong>: 10h × 3600sec × 초당 1킬 = <strong class="font-semibold text-text-0">36,000 회 RollDrops</strong> — 수백 ms ~ 1s+ CPU 스파이크. 24h 캡 시 86,400회 — 체감 프리즈 위험.</li><li class="mb-1"><strong class="font-semibold text-text-0">성능 측정 필요</strong>: Unity 6 모바일 Mono에서 Dictionary Lookup + System.Random.NextDouble 기준, 36,000회 ≈ 100~300ms 예상 (중급 기기). 허용 범위지만 여유 없음.</li></ul>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">2.3 옵션 B — 집계 공식 (평균 처치율 × 경과시간)</h3>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>killsTotal   = killsPerSec × elapsedSec
goldTotal    = killsTotal × avgGoldPerKill(currentFloor) × prestigeBonus.GoldMul
expTotal     = killsTotal × avgExpPerKill(currentFloor) × prestigeBonus.ExpMul
drops        = ExpectedDrops(killsTotal, dropTable, currentFloor, mobKind)  // 확률 × 횟수
ppGained     = floor((elapsedSec / 3600) × maxFloor × 0.05 × prestigeBonus.IdleRateMul)</code></pre>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">장점</strong>: O(1) 계산. 10시간·24시간·48시간 모두 동일 1ms.</li><li class="mb-1"><strong class="font-semibold text-text-0">단점</strong>:</li><li class="mb-1">드롭 표현력 상실 — &quot;레어 1개, 에픽 0개&quot; 같은 정수 결과가 평균 개수(예: 0.37개)로 표현됨 → 반올림 or 확률 추첨 한번으로 해결해야.</li><li class="mb-1">마일스톤 &quot;방치 중 돌파&quot; 시퀀스를 잡기 어려움 (언제 100→101→102 도달?) — 별도 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">FloorProgressEstimator</code> 로 수식화 필요.</li><li class="mb-1">&quot;방치 동안 층 자동 진행 허용&quot; 여부 (§6 Q3) 에 따라 복잡도 극심 차이.</li></ul>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">2.4 옵션 C — 하이브리드 (구간 샘플링 + 마지막 구간 리플레이) <strong class="font-semibold text-text-0">권장</strong></h3>
<pre class="my-4 overflow-x-auto rounded border border-border bg-bg-1 p-4 text-[13px]"><code>cappedSec = min(elapsedSec, idleCapHours × 3600)

// Phase 1: 첫 구간 = 공식으로 집계 (cappedSec - 3600 초)
if cappedSec &gt; 3600:
  bulkSec   = cappedSec - 3600
  bulkBundle = AggregateFormula(bulkSec, dropTable, milestoneCatalog, prestigeBonus)

// Phase 2: 마지막 1시간 = 이벤트 리플레이 (최대 3600회)
tailSec      = min(cappedSec, 3600)
tailBundle   = ReplayEvents(tailSec, dropTable, ..., rng)

// 합산
finalBundle = bulkBundle + tailBundle</code></pre>
<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">장점</strong>:</li><li class="mb-1">리플레이 횟수 상한 <strong class="font-semibold text-text-0">3,600회 고정</strong> — 10h든 24h든 성능 동일.</li><li class="mb-1">마지막 구간은 이벤트 로그로 &quot;방치 보고서&quot; UI 표현 가능 (&quot;최근 1시간 동안 에픽 2개 획득&quot; 등).</li><li class="mb-1">Bulk 구간은 집계 수식 → 긴 방치에도 즉시 응답.</li><li class="mb-1"><strong class="font-semibold text-text-0">단점</strong>:</li><li class="mb-1">구현 복잡도 옵션 A·B 합산 → 테스트 커버리지 2배.</li><li class="mb-1">마일스톤 돌파 타이밍은 여전히 추정 (Phase 1 집계에서 &quot;이 1시간 구간 동안 105→108층&quot; 식 추정).</li><li class="mb-1"><strong class="font-semibold text-text-0">적합성</strong>: 1인 파트타임 + 모바일 타겟 + 방치형 핵심 체험 (&quot;돌아왔는데 짜잔!&quot;) 모두 만족. <strong class="font-semibold text-text-0">Sprint 03 권장</strong>.</li></ul>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">2.5 각 옵션의 드롭·마일스톤·PP 처리 차이</h3>

<h2 class="mb-3 mt-6 text-[18px] font-semibold text-gold-light">3. 타임스탬프 관리 &amp; 치팅 방지</h2>
<h3 class="mb-2 mt-5 text-[15px] font-semibold text-text-0">3.1 로컬 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">DateTime</code> 신뢰 가능한가</h3>

<ul class="mb-3 ml-5 list-disc text-text-0"><li class="mb-1"><strong class="font-semibold text-text-0">증상</strong>: iOS 는 앱이 백그라운드 진입 후 약 30초 내 Suspend. 이후 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">Update()</code> 정지. <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OnApplicationPause(true)</code> 는 Suspend 직전 호출 보장이 약함 (Unity 버전·OS 조합 변수).</li><li class="mb-1"><strong class="font-semibold text-text-0">리스크</strong>: 유저가 백그라운드로 돌린 후 30초 뒤 앱이 Suspend → 10분 뒤 다시 열면 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OnApplicationPause(false)</code> 가 먼저 호출됨. 이때 <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">_lastTickUtc</code> 가 Suspend 직전이 아니라 앱 진입 시점이면 오프라인 계산 누락.</li><li class="mb-1"><strong class="font-semibold text-text-0">완화</strong>:</li><li class="mb-1"><code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OnApplicationPause(true)</code> 호출 시 <strong class="font-semibold text-text-0">즉시</strong> <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">IdleSaveService.Save()</code> + <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">lastTickUtc = DateTime.UtcNow</code> flush.</li><li class="mb-1"><code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">OnApplicationPause(false)</code> 는 재계산만 수행 (Save는 재진입 후 1틱 지나야 다시).</li><li class="mb-1">추가 안전망: <code class="rounded bg-bg-3 px-1.5 py-0.5 font-mono text-[12px] text-gold-light">Update()</code> 내부에서 1분에 1회 Save flush (1분 미만 차이면 iOS Suspend에도 큰 손실 없음).</li><li class="mb-1"><strong class="font-semibold text-text-0">Sprint 03 범위 내 해소 가능</strong>. 전담 테스트: 실제 iOS 실기 테스트는 Phase 3+ 빌드 파이프라인 가능 후 재확인 (CP-I8 체크리스트 이월).</li></ul>
